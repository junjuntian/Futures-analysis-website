# 聪明资金系统（席位 Alpha）：设计方案 v1

起草日期：2026-08-10。状态：**待运营者确认口径**（见第 7 节），确认前不实施。

一句话定位：**不是龙虎榜跟单**。是「历史验证过的席位行为 × 持续建仓 × 多席位共振 × 价格确认」
的规则引擎，回答的问题从"这个品种会不会涨"变成"有信息优势的资金是否在持续做多、市场是否
已经接受"。

## 0. 与现有工程的关系

- 前置依赖：`SEAT_AND_SPREAD_REQUIREMENTS.md` 第 6 节的**采数据阶段先完成**，不跳步。
- 输入 = `TWO_TABLE_DESIGN.md` 的两张表：表一（行情，含 `open_interest`）+ 表二（席位持仓）。
  **不需要为本系统新增采集源**。
- 在"写规则"阶段的位置：价差引擎、席位成本引擎之后的第三个引擎。
- 数据源口径不变：**官方优先**。三禾只是 DCE 席位来源与对拍验证源，不是本系统的主数据源。
  （运营者最初表述"用三禾的数据做这个系统"，实际含义是"用席位持仓数据"——该数据已在
  采集计划内，官方源覆盖比三禾深得多：CZCE 2012 起、SHFE 2008 起，三禾仅 2023-08 起。）

缺口，须在 M1 补齐：

1. **主力合约序列**。品种级收益序列必须有它。平台 MVP 不自动生成连续合约（DEC 口径），
   本系统只需一个最小规则：**当日 OI 最大者为主力，次日生效，不回切**；品种日收益 =
   当日主力合约的当日涨跌，**换月日不跨合约计算收益**（用各自合约自己的前收盘）。
2. **DCE 席位回溯定案**。`SEAT_AND_SPREAD_REQUIREMENTS.md` 4.2 记"大商所官方
   memberDealPosi/batchDownload 已实证可回溯 2013"，而 `TWO_TABLE_DESIGN.md` 末尾记
   "大商所席位 2023-08 之前：三禾也没有，无解"。**两处矛盾，须重探测定案**。对本系统
   影响大：JM/JD/LH 若只有 3 年数据，单席位统计功效不足，这三个品种将只能跑合计基线因子。
3. **OI 口径核验**。三家持仓量的单双边口径须实测确认。本系统规避方式：`Flow` 只在
   同品种内做 Z 标准化后使用，不跨品种直接比较绝对值。

## 2. 记号与预处理口径

对（席位 m，品种 v，日 t），一律使用**品种汇总行**（`is_variety_total = true`）：

- `Net = long − short`
- `ΔNet = Δlong − Δshort`，**必须用交易所公布的 `change` 字段聚合**，不得用相邻两日
  `Net` 相减——席位掉榜再回榜时相减会造出假跳变。
- `Flow = ΔNet / OI(v,t)`，OI 为该品种全合约持仓量合计。
- **掉出前 20 = 不可知，不是 0**。缺失日不产生事件、不前向填充、不进统计。
  （与 `SEAT_AND_SPREAD_REQUIREMENTS.md` 2.4 同口径。）

## 3. 席位能力评分（Skill）v1 —— 系统核心

### 3.1 事件定义

席位 m 在品种 v 的**方向事件**：

- `|Flow| ≥ Q80`（该 (m,v) 过去 250 交易日 `|Flow|` 的 80 分位），方向 = `sign(ΔNet)`。
- (m,v) 历史不足 120 个有效观测日不出事件。

### 3.2 收益对齐（防未来函数）

- 榜单当日盘后公布 ⇒ 事件日 t 的信息**最早 t+1 可用**。
- 前向收益以 t+1 的执行价为起点：`R_h(t)` = 从 t+1 执行价持有 h 日的品种收益，h ∈ {5, 10}。
  执行价主口径 = t+1 开盘价（备选 t+1 收盘，两套都报，见第 5 节）。

### 3.3 单元评分（席位 × 品种 × 方向）

每个单元统计：事件数 N、方向收益均值 `DR = mean(sign × R_h)`、t 值、命中率、
分年同号稳定性 S（各自然年 DR 同号的年份占比）。

**v1 判定为二值，不做 0–100 精细分**：

```
强席位单元 ⇔ N ≥ 30 且 t ≥ 2.0 且 S ≥ 0.6
```

理由：样本量撑不起精细分数，60 分和 72 分的差异是假精确。0–100 分留 v2。
指数权重取 `w ∝ clamp(t, 0, 4)` 归一。

### 3.4 防假统计协议（缺一不可）

1. **滚动训练/验证分离**：过去 3 年（不足则 ≥2 年）训练窗选强单元 → 只在随后 6 个月
   验证窗计信号表现 → 每 6 个月滚动重选。禁止全样本挑席位再回测全样本。
2. **holdout 留任**：训练窗选出的强单元，验证窗 DR 必须同号才保留进下一期名单。
   ~8 品种 × ~50 活跃席位 × 2 方向 ≈ 800 个假设，纯 t≥2 会留下几十个假阳性，
   靠这条杀掉。
3. 掉榜 ≠ 0（第 2 节）。
4. T+1 执行（3.2）。
5. 换月不跨合约（第 1 节）。
6. **运营者先验席位不豁免**：运营者点名的席位作为白名单优先评估、结果人工对照，
   但同样过统计验证——先验用来校验系统，不用来跳过检验。

### 3.5 合计基线因子（必做，codex 方案缺失的一块）

运营者经验"**综合**是最赚钱的席位"，落成可计算定义：

```
Top20Net(v,t)  = Σ 上榜席位 long − Σ 上榜席位 short
ΔTop20Net(v,t) = 用 change 字段聚合
```

它不依赖单席位识别、没有掉榜缺失问题（榜单整体永远在），是国内期货实证最稳健的
持仓类因子。**v1 先跑通它作为基准：单席位 Skill 体系扣费后跑不赢这个简单合计因子，
就不值得维护席位名单**——这是整个项目的第一道判定门。

## 4. SmartMoney 指数与三阶段信号

- 指数：`z* = Σ_强席位 w_m × Z(Flow_m,t)`，`SmartMoney = 100 × tanh(z*/2)` ∈ (−100, 100)。
- 持续性：近 5 日强席位合成 ΔNet 同向天数。
- 三阶段（全部可回测、无主观项）：

| 阶段 | 条件 | 动作 |
| --- | --- | --- |
| ① 异动 | `|SM| ≥ 40` | 观察，不交易 |
| ② 持续 | 连续 3 日同向且 `|SM|` 抬升 | 候选，不交易 |
| ③ 确认 | 收盘价创 20 日新高/新低 且 品种 OI 5 日净增 | 产生信号 |

- 退出（先触发者生效）：`|SM|` 跌破 40 或反号；或收盘价跌破/升破 20 日均线。

## 5. 回测协议

- 成本：各品种交易所手续费 + 单边 1 个最小变动价位滑点。
- 执行：主口径 T+1 开盘价，敏感性口径 T+1 收盘价，两套结果都出。
- 基准三件套：① 品种买入持有；② 20 日突破简单趋势（不看席位）；③ Top20Net 合计因子。
  **席位系统必须扣费后跑赢 ② 和 ③ 才认定存在席位 Alpha**。
- 每笔信号可回查明细：触发当时哪些席位、各自 Flow、SM 值——运营者能用盘感逐笔校验。

## 6. 实施顺序（遵守"先采数据 → 写规则 → 界面"）

| 里程碑 | 内容 | 产出 |
| --- | --- | --- |
| M0（前置） | 现行采集阶段完成；DCE 席位回溯定案 | 两张表灌满 |
| M1 | 主力合约序列、品种收益序列、OI 口径核验 | 数据就绪报告 |

| M3 | 判定门：验证窗扣费后有增量 → 引擎进 Rust 每日盘后跑；无增量 → 只上"席位行为观察页"，不上信号 | 拍板记录 |
| M4 | 界面：品种 SmartMoney 页 + 席位能力矩阵页 + 信号/退出状态 | 页面 |

M2 用 Python 而非直接进 Rust：研究阶段公式会反复推翻，离线迭代成本低一个量级；
**先证明这 8 个品种上席位 Alpha 存在，再工程化**。定稿公式才进 Rust 生产管线。

## 8. 相对 codex 原方案的修正

1. 数据源：不是"用三禾做系统"——自有库官方源覆盖深得多（CZCE 12 年 / SHFE 18 年
   vs 三禾 3 年），三禾定位为 DCE 来源 + 对拍。
2. 补了 **Top20 合计基线因子**：比单席位稳健、无缺失问题，且是第一道判定门。
3. Skill v1 二值化（强/非强），不做 0–100 精细分——样本不够，精细分是假精确。
4. "滚动训练"落成明确协议：3 年训练 / 6 个月验证 / holdout 同号留任，解决 800 个
   假设的多重比较问题。
5. 明确了 ΔNet 必须用 `change` 字段聚合而非相邻日相减（codex 方案未提，掉榜边界会造假信号）。
