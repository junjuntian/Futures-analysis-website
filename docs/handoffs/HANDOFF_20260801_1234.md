## 3. 三项 P1 闭环记录

### 3.1 删除 VPS 遗留 bootstrap-token（DEC-026 闭环）

- 背景：`DEC-026` 要求首个用户创建成功后删除文件来源的 bootstrap token。实态是 `/etc/futures-platform/secrets/bootstrap-token`（400 root，64 字节，2026-07-26 14:49 创建）一直残留。
- **根因（重要，代码缺陷）**：`rust/apps/api/src/auth.rs` 在 bootstrap 成功后确实执行 `fs::remove_file(path)`（约 520 行），但容器内路径 `/run/secrets/bootstrap-token` 来自 `docker-compose` 的 **`:ro` 只读挂载**，删除必然失败，且 `let _ =` 将错误静默吞掉。即该决策在生产部署拓扑下永远不会自动生效。
- 已做：2026-08-01 在 VPS 宿主侧 `rm /etc/futures-platform/secrets/bootstrap-token`。删除前已核验双重防线均生效：`system_settings.bootstrap.completed` 标志与 `users` 非空检查（`user_count != 0` 即返回 `bootstrap_closed`）。
- 验证：删除后 API 容器保持 healthy（token 文件读取为容错逻辑 `.ok()`，缺失不影响启动）；`POST /api/v1/auth/bootstrap` 携无效 token 实测返回 `403 bootstrap_token_invalid`。
- 遗留：①当前 API 进程内存仍持有启动时读入的旧 token 值，数据库双防线已兜底，下次容器重启/重新部署后彻底清除，无需为此专门重启；②建议后续将 auth.rs 的静默 `let _ =` 改为「删除失败时记录警告/审计」，或在部署文档写明「宿主侧手动删除」为标准步骤——二选一，归入下一阶段普通改进项，不阻断。
