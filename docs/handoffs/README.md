# Agent 交接机制

本文定义上下文轮换和 Agent 交接规则，适用于主 Agent、Planner、Generator 和 Evaluator。

## 触发条件

- 当前 AI 判断上下文即将不足，或剩余上下文不足以安全完成下一个完整子任务。
- 当前阶段刚完成，适合切换新会话。
- 已积累大量代码、日志或审查内容。
- 用户明确要求换新 AI。
- AI 已无法可靠记住前序决策和修改范围。

## 交接流程

1. 旧 AI 立即停止领取新任务。
2. 可以完成当前正在执行的最小原子操作，但不得开启新的开发内容。
3. 检查并记录 Git、未提交文件、任务状态、已确认决策、阻塞问题、测试结果、VPS 状态、数据库迁移、服务端口和下一步第一条操作。
4. 创建不可覆盖文件：`docs/handoffs/HANDOFF_YYYYMMDD_HHMM.md`。
5. 更新 `docs/handoffs/LATEST.md`,只指向并概括最新交接状态。**保留策略
   (2026-08-16 运营者拍板)**:工作树只留最近约三份交接 + LATEST,更早的
   定期删除,git 历史即归档——LATEST 不再维护逐段历史区。
6. 交接文档不得包含密码、API Key、Cookie、Token、主密钥、数据库明文凭据或其他秘密。
7. 若当前代码处于可提交状态，创建独立提交：`docs: add agent handoff checkpoint`。若不可提交，必须完整记录未提交文件和修改意图，不得强行提交错误代码。
8. 完成后提示：“当前上下文工作已完成交接，请清空上下文并由新 AI 根据 docs/handoffs/LATEST.md 接管。”

## 交接文档模板

每份 `HANDOFF_YYYYMMDD_HHMM.md` 必须使用以下标题，不得省略：

```markdown
# Agent Handoff

## 当前目标
## 当前阶段
## 已完成
## 正在进行
## 尚未完成
## 关键决策
## 修改过的文件
## 未提交修改
## Git 分支与提交
## 本地测试结果
## 生产 VPS(qh)状态
## 数据库迁移状态
## 已知问题和风险
## 下一步第一条操作
## 新 AI 必读文件
## 禁止重复或禁止修改事项
```

记录要求：

- `Git 分支与提交` 必须包含当前分支、HEAD commit、最近提交摘要和 `git status` 结果。
- `未提交修改` 必须说明每个文件的修改目的；不能只写“有改动”。
- `本地测试结果` 必须区分“已运行并通过”“已运行但失败”“未运行及原因”。
- `生产 VPS(qh)状态` 必须记录是否实际核对；未连接时写明“未核对”，不得推测。
- `数据库迁移状态` 必须记录已执行迁移编号；未创建数据库时写明“未执行迁移”。
- `禁止重复或禁止修改事项` 必须包含原始 Word 设计方案不得修改、不得写入秘密、不得重复已验收工作。

## 新 AI 接管规则

1. 使用全新上下文开始，不依赖旧聊天记录。
2. 依次阅读 `AGENTS.md`、`PLANS.md`、`docs/DECISIONS.md`、`docs/handoffs/LATEST.md`、LATEST 指向的完整交接文档、当前 Phase 计划和最近一次 Evaluator 审查报告。
3. 实际执行 `git status`、`git branch --show-current`、`git log -5 --oneline`。
4. 涉及生产 VPS(qh)时，必须通过 MCP SSH 核对容器、服务、部署版本、健康检查和未完成迁移。
5. 不盲目信任交接摘要；以 Git、数据库迁移记录和运行环境事实为准。
6. 核验完成后先简要记录接管结果，再从“下一步第一条操作”继续。
7. 不重复已经完成并验证通过的工作。
8. 发现交接文档与实际状态不一致时，以事实为准并更新交接文档。
9. 交接文档不能替代正式设计文档；长期决策写入 `docs/DECISIONS.md`，阶段状态写入 `PLANS.md`。
