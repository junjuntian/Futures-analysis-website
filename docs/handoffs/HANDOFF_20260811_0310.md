# Agent Handoff

## 当前目标

两个产品上线可用：**套利页**（自由价差，运营者称为核心）与**席位页**（席位持仓 /
建仓过程）。本轮把套利页从三禾切到自建价差引擎，把两张历史表接上日更，并修掉一个
让运营者看不到任何数据的 workspace 错位。

历史都在运营者名下可用。剩余唯一未完成项是三禾大商所席位历史的采集与装载。

## 关键决策

### 1. 自由价差改用自建引擎，三禾降为可回退备选（`DEC-046`）

切换只是请求里的一个字符串，出问题能立刻切回去，也便于把两边数字摆在一起比。
`DEC-042` 授权的三个三禾只读端点维持不变。

### 2. 大商所行情日更改由新浪供给（`DEC-047`）

- **大商所四条路全断**（2026-08-10 实证，每个地址各一次请求）：官网全站 412（含首页）；
  akshare 的 `get_dce_daily` 打的是同一个站，拿回挑战页；东财 `push2his` K 线接口
  **第一个请求就被断开**、`push2` 行情 502。**不是限频**——最初判成限频是错的。
  东财 `futsse-static` 目录接口仍 200 且当日更新，但只有合约元数据、无价格。
- **这不是引入新源**：`price_history` 里大商所 2025-01-02 之后的行情**本来就是新浪的**
  （回填补缺口写的 11,262 行）。真正的选择是让这条已在用的路继续走，还是停更。
- **与交易所年度文件逐字段对照**：843 个重叠日，收盘/结算/开盘/最高各 **837 天完全
  相同**；持仓量**恰好 2.0000 倍**（交易所双边、新浪单边），843 天无一例外。
- **剩下 6 天的差异原因已查明**：2024-09-25 一天新浪把六个合约的结算价全写成 `0.0`；
  另三天是当日只成交 1–2 手的合约日，收盘价偏而结算价与交易所完全相等。
- **四道到货检查**（`deploy/collector/sina-dce-daily.py` 的 `usable`）：价格 `<= 0` 丢弃、
  收盘越出当日 `[low, high]` 丢弃、成交量 `<= 0` 丢弃、两个价格都没有丢弃。被拒的行
  **连原始值一起打进日志**。测试在 `collector/tests/test_sina_dce_daily.py`，用的是上述
  两处真实故障的数值。
- **已知且未掩盖的缺陷**：极低成交日新浪收盘价可能与交易所差几十点。**没有加成交量
  阈值去修饰**——阈值是编的。运营者已知悉并接受。
- **席位不走新浪**：大商所席位经 `eastmoney_seats_v1` 是通的，08-06、08-07 都采到了。

### 3. 数据曾整体落在错误的 workspace（本轮最重要）

生产上有 **31 个 workspace**，绝大多数是历次验收留下的 E2E 空间。回填装载脚本用
`select id from workspaces order by id limit 1` 挑目标，取到的是 UUID 最小的
`018f0000-0000-7000-8000-000000000311`（`Phase 3C E2E 1`）。于是：

- 23.5 万行价格、380 万行席位落在测试空间

  2 个成员、他的两条收藏在此）只有每日采集写的最近八天

**这个错不报任何异常**，而且此前每次验证都用「行数最多的那个 workspace」取数，
所以一直在验运营者看不见的那一份。已用一个事务搬迁完成（先 `pg_dump` 备份两张表到
`/root/history_before_workspace_move.dump`，149M）。

**今后判据：有 `market_prices` 的那个 workspace**——每日采集以运营者账号登录写入，
有行情的空间必然是他在用的。已写进 `backfill/README.md` 置顶段落，并修进
`backfill/load_sanhe_seats.sql`、`deploy/collector/load-dce-daily.sql` 和服务器上的
`/opt/futures-platform/load_db.sh`（原件备份 `/root/load_db.sh.before-workspace-fix`）。

**同源的第二个错**：`product_instrument_scope` 是逐 workspace 播种的，join 它而不限定
workspace，一份 CSV 会被复制成 31 份——真发生过，3639 行灌出 112,809 行，已在同一
