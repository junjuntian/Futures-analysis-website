## 0. 先读这四条

1. **全站颜色收进双主题 token,业务代码不许再写死十六进制色。**
   CSS 层用 `var(--tv-*)`(定义在 `frontend/src/styles.css`);ECharts 不认
   CSS 变量,图表颜色走 `frontend/src/chartTheme.ts` 的 `chartTokens()`,
   **两处同源双份维护,改一边必须同步另一边**(两个文件顶部注释都写了)。
2. **涨跌语义固定红涨绿跌**(国内期货惯例):`--tv-up` 红(#F23645 系)、
   `--tv-down` 绿(#089981 系)。借 TradingView 的色相与底色,不借它的涨跌
   方向。盈利=红、亏损=绿、K 线阳红阴绿,全站一致,**不许翻转**。
3. **主题切换机制**:深色 = `html.dark` 类(Element Plus 官方约定);顶栏
   太阳/月亮按钮切换,存 localStorage(键 `fap-theme`),缺省深色;
   `index.html` 有防闪屏内联脚本;**App.vue 给 `<router-view>` 绑了
   `:key="themeMode"`,切主题强制重挂载当前视图**——这是图表跟着换色的全部
   机制,视图里不需要也不要再写主题 watch。
4. **本地视觉验收用 `npm run dev:proddata`**(或 `frontend/scripts/dev-proddata.cmd`):
   本地样式 + 生产数据代理。两个坑都踩过并写在 `vite.config.ts` 顶部注释:
   本机系统 DNS 对 `shejimao.trade` 返回污染 IP,代理必须直连生产真实 IP
   (生产换机要同步改);`/smart-money/` 代理前缀必须带尾斜杠,否则吞掉
   SPA 路由 `/smart-money-view` 白屏。

## 1. 改了什么

- **token 层**(`styles.css` 重写):浅色 #f0f3fa/#fff/#e0e3eb,深色
  #131722/#1e222d/#2a2e39,主色 #2962FF;Element Plus 全套变量映射到 token,
  卡片/表格/弹窗/按钮质感统一(圆角 8/4,阴影收敛)。
- **EP 深色特异性坑(重要)**:EP 的 `dark/css-vars.css` 用 `html.dark`
  选择器定义整套 `--el-*`,特异性压过 `:root` 上的映射——**必须在
  `html.dark` 下把映射重申一遍**,否则深色主题的 EP 主色退回默认蓝
  #409eff。styles.css 里有完整的重申块与注释,别删。
- **chartTheme.ts**:双主题各一套图表 token(轴/网格/tooltip/滑钮/叠年色板/
  导出底色)。`chartTokens()` 必须在构建 option 的函数体内调用,不许提到
  模块顶层(重挂载时要取到新值)。
- **七个视图 + 两个组件**全部硬编码色迁移(约 150 处),K 线
  color/color0 显式钉死红涨绿跌;图表导出(PNG/SVG)底色跟主题,深色导出
  不再是白底浅线。
- **三处语义修正**(视觉审查产物):
  1. 机构资金页盈亏 pill 原为绿盈红亏,与同屏收益列(红盈)自相矛盾,已统一

## 3. 别踩的坑(本轮实证)

- **Smarty/旧栈无关**,这是 Vue 3 + Element Plus 2.11 + ECharts 6;改样式先
  看 styles.css 的 token 清单,缺 token 用最接近的,不要私加十六进制。
- el-select 弹层有 ~200ms 淡入,自动化截图常截到半透明半程,不是 bug。
- 主题切换会重挂载视图 → 页面内未持久化的选择(如自由价差的四个下拉)会
  清空,这是 `:key` 机制的已知代价,单人面板可接受;席位页的选择存
  localStorage 不受影响。
- 测试环境(jsdom)缺省深色(theme.ts 的 initialMode 无存档时返回 dark),
  断言主题相关值要么 mock chartTheme 要么显式设置。
