## 0. 部署铁律(先读这条,违反过三次)

**每次部署都必须显式确认这四点,缺一不可:**

1. **`run_live_collection` 必须显式传值。** 与采集/Phase 4A 无关的变更一律传 `false`,否则 4A 验收会真采五交易所,耗时约 1 小时(全花在 DCE 412 → 新浪 fallback → 超时上),而不是 15 分钟。
2. **传了 `false` 还要确认脚本里有短路代码。** 部署前执行 `grep -c PHASE4A_RUN_LIVE_COLLECTION rust/tests/phase_4a_e2e.sh`,**结果必须 ≥1**。开关由 workflow 传递、由 e2e 脚本执行,两者缺一就是"开关空转",跑起来才发现已经晚了。**此坑已踩:合并分支时用主线脚本覆盖了候选脚本,短路代码丢失,开关照传但无人响应,白跑一小时。**
3. **镜像必须本链新构建。** 不要复用历史 run 的 digest。
4. **验收脚本的 Origin 必须与部署生效的 `PUBLIC_ORIGIN` 一致**,否则验收自己会被 Origin 校验拦下(已由 workflow 自动传 `PHASE4A_ORIGIN`/`PHASE5A_ORIGIN` 解决,勿删)。

**正常耗时基准:构建约 8 分钟 + 部署验收约 7 分钟 ≈ 15 分钟。超过 20 分钟仍未出验收标记,基本可判定 4A 在跑真采,应立即检查上面第 2 条。**

取消部署的正确方式:`gh run cancel` 之后,**必须再上 VPS 清理残留**——GitHub 取消不会杀掉已在 VPS 启动的脚本与 collector 容器:
```

docker rm -f phase4a-collector-e2e
```
