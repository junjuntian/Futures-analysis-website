## 3. P0：相关阶段开始前确认

### `OPEN-PORT-002` 交易细节

问题：

- 是否支持同一合约同时保留多头和空头仓位展示。
- “平今/平昨”如何保存和参与手续费计算。
- 具体手续费、合约乘数和保证金参数的权威来源及版本方式。

已确定约束：原始成交不可覆盖、默认 FIFO、已实现净盈亏包含手续费、胜率按完整 `trade_group`。

## 4. P1：详细设计前确认

### `OPEN-AI-002` Provider 与数据政策

问题：默认 Provider/模型、允许地区、数据保留政策、敏感字段、失败回退和预算。

已确定约束：OpenAI、Grok、Gemini 统一 Provider 接口；API Key 使用信封加密；AI 默认只读且不能执行任意 SQL。

### `OPEN-AI-003` 对话保留

问题：AI 对话、工具结果和用量日志保留多久，用户能否删除或导出。

### `OPEN-OPS-001` 容量与性能

问题：用户数、文件大小、每日导入行数、行情总行数、并发任务、接口 P95 目标。

已确定资源结论：裁剪后现有 1GB 内存、25G 磁盘 VPS 支撑全部阶段；五个核心容器实测约 310MB；席位全历史预计增长 5–15GB，磁盘达到 80% 水位时扩盘、不换机器。其余性能目标仍待确认。

影响：上传限制、连接池、分块、索引和是否分区。

### `OPEN-OPS-002` 备份目标

问题：RPO、RTO、保留周期、异地位置和恢复演练频率。

### `OPEN-OPS-003` 数据保留

问题：原始文件、staging、采集任务及标准化 CSV、审计、图表和报告分别保留多久。

### `OPEN-SEAT-001` 席位分类治理

问题：分类证据来源、批准人、可信度等级和版本有效期。
