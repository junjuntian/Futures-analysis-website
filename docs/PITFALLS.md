## 一、生产库操作

- **用旧检出的脚本重算,把 45 天新列刷成 NULL**(2026-08-18)。`/opt/futures-platform`
  是旧 git 检出,只有 `load/` 被采集用作 CSV 落盘,**代码一律不从那取**。手动重算
  唯一正确来源:`. /var/lib/futures-platform/deployments/stable.env` 后用
  `$previous_release_dir/deploy/collector/…`。
- **grep 剥 `commit;` 做"跑一遍再回滚",转义失效把 DDL 真落进生产**(2026-08-17)。
  要么复制一份改好的脚本,要么不在生产库上试。迁移因此全部要求幂等
  (`add column if not exists`、`drop constraint if exists` + `add`)。
- **只读验证截掉写操作,约束从没被检验过**:`move >= 0` 写错,部署后全量重算才被
  check 拦下(202608170003)。只读验证必须另配值域检查。
- **sane 护栏拦住的是脏数据,我却放宽了护栏**(2026-08-18,**已勘误**):回填撞
  `prev_years_position = −12.26`,我判定「真实观测、百分位区间被撑爆」并放宽护栏
  到 ±100(迁移 202608180002);当天晚些查证发现那是收盘价 0 造成的假价差
  (见本文四·收盘价 0 与 `DEC-073`)。**护栏本来是对的。**
  insert 单语句原子回滚,现网全程无损——但**约束报错时的第一动作是去查被拦那行的
  原始数据,不是放宽约束**。修完根因重算后实际值域只有 −2.85~5.01,护栏已由
  202608180004 收回 ±10(**先重算再收紧,顺序反了会被 check 拒绝**)。
- **RLS 下无上下文查询返回 0 行假象**:业务表全 FORCE RLS,连 owner 也被过滤。
  核数要 `set local role` + `set_config('app.current_workspace_id', …)`,或用管理员
  绕 RLS。runtime 角色 nologin,psql 冒烟用 `set local role futures_runtime`。
  库名是 `futures_platform` 不是 `futures`。

## 二、发布链

- **dispatch 的 SHA 凭记忆打错被门禁拦下**:必须从 `git log` 复制完整 40 位;
  digest 不要从构建日志 grep(secret 打码会污染),用 preflight 脚本取。
- **建镜像到部署完成之间推了提交**(包括纯文档提交)→ `acceptance_sha` 守卫拒绝,
  镜像整套重建。文档等部署完再推。
- **同分支并发**:另一会话在你 push 后又 push,workflow_dispatch 取分支 HEAD 构建,
  传旧 SHA 就出身不匹配。部署前 fetch 核对 HEAD。
- **新迁移忘进 `deploy-futures.yml` 显式清单**:代码上线 schema 没到,全站 500。
  加迁移与改清单必须同一笔提交。
- **改申报/契约只改了消费方**:生产方代码没进提交,值恒空回退。改任何"值"提交前
  全仓库 grep 旧值;生产方消费方同一笔提交。
- **CI clippy 按 `-D warnings` 跑**:本地裸 `cargo clippy` 数 error 是 0 也可能挂
  CI(如 doc_lazy_continuation)。本地第 0 步就带 `-- -D warnings`。
- **e2e 脚本搬代码遗留未定义变量/不存在文件,第一次真实执行才炸**。改采集/验收
  脚本后 `bash -n` + shellcheck,并检查引用的夹具文件存在。
- **部署偶发 `DEPLOY_FAIL ghcr_login_failed`(token_http=403)**:2026-08-18 出过一次,
  同一套 digest、同一条链、四十分钟前刚成功过,原样重发 dispatch 即通过。这是
  GHCR 侧的瞬时拒绝,不是权限配置问题——**先原样重试一次再排查**,不要一上来就
  去动 workflow 的 permissions 或换 token。生产在这种失败下不受影响:镜像还没拉,
  切换没发生,`stable.env` 仍指向旧发布。

## 三、生产服务器(qh)运维

- **cron 的 `CRON_TZ=Asia/Shanghai` 在这台机器上不生效**(三例):写北京时间会按
  UTC 解释,任务在凌晨跑或从未跑过。一律写 UTC。
- **"脚本里写了"≠"被执行过"**:采集器非零退出 + `set -e` 曾让日更投影**从未**
  自动成功;`docker images | grep | head` 在 pipefail 下 SIGPIPE 141 杀全脚本
  (禁用 head 截断长流,用 awk 首匹配)。验证管线要验每一步的产物时间戳。
- **服务器上的文件副本会漂**:`/opt/futures-platform/parsers.py` 曾是仓库旧副本,
  郑商所世纪判错每天发生。engine/ 现已随发布包自动装到
  `/opt/futures-platform/smart-money/`(2026-08-18 实证 md5 一致),
  "引擎要手动 install" 的旧说法作废。
- **ssh_execute 长 sleep 必超时**:超时不杀远程进程,别重发命令(会双跑)。
  长任务 nohup + 日志文件,60 秒短轮询;等待用 `grep -q EXIT= 日志` 判完成。
- **ssh_execute 传大文件禁用 heredoc**:单行大 base64 经 heredoc 会中段变形
  (同尺寸字节替换,极难察觉)。用 `printf '%s' '<b64>' | base64 -d > 文件`,
  落地后 **md5 与本地对拍**,不一致不许执行。

## 四、数据口径

- **榜上无名 ≠ 清仓**:龙虎榜是前 20 截断,小席位掉榜常在门槛边缘。回榜日
  `回榜量 − 当日增减 = 前日全量仓` 可反推;反推行 `reboard_inferred` 不进任何
  汇总与规则,只作展示(吸收律:任何一腿增减缺失,整个反推作废)。
- **空头的「加仓/减仓」要按绝对值判,不能用净持仓的代数差**(2026-08-18):
  净空 −10,621 → −7,143 的代数差是 +3,478,看着像加仓,实际是空单减了 3,478 手。
  加减说的是仓位变大还是变小,与方向无关。
- **缺席 = 未知 ≠ 零**:掉榜日持仓一律 NULL,补零会一路错到成本引擎。
  增减量渲染三态:undefined=无行计 0 / null=有行但源没给(污染整个求和)/ number。
- **多源重复行灌水**:同一天同一合约在多个源下各一行。数"共同交易日"必须
  `distinct trade_date`(曾把 58 灌成 67,导致误判门槛);席位求和必须先按
  `member_key`(剥括号+别名)+ 来源优先级去重——东财写「一德期货(代客)」、
  三禾写「一德期货」,不归一化就把一家算成两家(2026-08-18,只有 DCE 双源
  并存的日子中招)。
- **临时分析 SQL 必须走与生产同一套归一化**,否则会把自己的写法问题误判成
  生产缺陷上报(「(代客)」事件:先报"影响面很大",查证后 Rust 展示路径因
  member_key 本就免疫,页面一直正确)。**上报缺陷前先查读时去重是否已覆盖。**
- **收盘价 0 不是价格,是「当天无成交」**(2026-08-18,9,795 行):郑商所如实写 0
  且结算价有效。只挡 NULL 不挡 0,价差就算成 `0 − 对手价`,假极值**永久钉死
  区间下界**(AP2603−AP2605 下界 −10753 vs 真实 −1313),造出假报警假拐头。
  取价一律 `coalesce(nullif(close_price,0), settlement_price)`。
- **PG boolean 经 CSV 是 't'/'f'**:pandas 按 str 读入后 `astype(bool)` 把 'f'
  判 True。必须 `.isin(['t','true','1'])`。
- **PHP/JSON 浮点**:float 整值印 2 不印 2.0;DATETIME 列 sqlx 必须 CAST。
  (这两条来自 shejimao 面板,同机型教训。)
- **名字长得像不等于是同一家,先查「有没有同日同榜并存」**(2026-08-19,格林)。
  合并归一之前必须问一句:这两个名字在同一天、同一合约、同一榜单上一起出现过吗?
  出现过就是**两家**——一张榜上同一家不可能占两个名次。「格林期货」与「大华期货」
  并存 266 次(2008-04-29~2013-09-17),是 2013 年吸收合并前的两家;而「格林期货」
  与「格林大华」只在交接当天 2014-03-27 并存、且持仓**逐笔相同**,那才是更名。
  判据是数据不是字面:并存次数 + 交接日数值是否逐笔相等 + 品种/交易所是否重叠。
- **「三个名字重复,删掉两个」——先查它们覆盖的范围是不是互补的**(2026-08-19)。
  运营者报「格林有三个名字,数据应该是一样的」,实态是三个各管一段:「格林大华」
  只在上期所大商所、「格林大华期货」只在郑商所、「格林期货」是 2014 年前的旧名,
  **品种零重叠**。照「重复」处理会丢掉郑商所三个品种的全部持仓与 2014 年前的历史。
  同一个现象(下拉里冒出好几个相似的名字)可以是重复,也可以是互补,**先看它们各自
  覆盖什么,再决定是删是并**。
- **源命名/更名**:乾坤→高盛(2026-05-26)等别名只在 `MEMBER_ALIASES`
  (spread_analytics.rs)一处维护,SQL 键与 Rust 归一都从它生成;engine 的
  alias 表保持同集。归一化只进展示/去重键,**过滤一律走原始列**(RLS 教训:
  regexp 进 WHERE 退化全表扫,会员下拉整个空掉)。

## 五、批量编辑与脚本工具

- **python 批量编辑:断言中途失败,前面的编辑已落盘、后面的没有**,然后照常
  commit(60a0d29 漏了迁移清单)。断言全部前置,或拆小笔逐个验证。
- **`s[:i] + helper + s[i:]` 插入时 helper 末尾带锚点文本 → 锚点重复**,产生
  unclosed delimiter。插入内容不要以锚点结尾。
- **锚点上下文不足,替换塞错同形代码处**(inferred 塞进错误的 mapper,编译器
  拦下)。锚点必须含足够独特上下文。
- **Bash heredoc 里的反斜杠会被二次转义**,Python 字符串尾随反斜杠直接
  SyntaxError 且整个脚本零编辑落盘。需要反斜杠用 `chr(92)`。
- **`\copy` 不做变量插值**:`\copy t from :'csv_path'` 会把路径当成空串,报
  `:: No such file or directory`。装载脚本一律写固定路径,与 run-collector.sh 里
  `docker cp` 的目标一一对应。(2026-08-18 重踩过一次——教训当时只写在
  load-seats-direct.sql 的注释里,**代码注释挡不住没读那个文件的人,所以提到本文**。)
- **PowerShell 5.1 按 GBK 读 UTF-8**:改中文文档禁用 Get-Content/Set-Content,
  用 Edit 工具或 Python;改完查乱码字符数。

## 六、回测与统计方法

- **单品种回测出的参数是过拟合**:「回撤 150 点」实为鸡蛋 08-02 区间的 20%,
  换品种无意义(运营者抓的)。通用化=无量纲化;门槛不做旋钮;结论要求
  「相邻档同向」而不是挑峰值。
- **扫描挑出的最优参数当天采纳、次日被回测否决**(DEC-055「区间下 70%」)。
  参数采纳前先做逐年留一的样本外检验;LH/FG 相邻档正负翻转=噪音,不挑。
- **凭印象写数据结论**:「FG-SA 一次穿线」写进文档后被数据证伪(实际两次)。
  叙事入档前先跑一遍数。
- **修了生产的数据口径,必须回头重跑所有旧回测**(2026-08-18,DEC-075):
  回测导出与生产 SQL 用同一个取价条件是对的(同源才一致),但**同一个缺陷会同时
  污染两边,自己验证不了自己**。收盘价 0 修掉后重测,AP 的深档优势从 14.7pt 缩到
  5.1pt、逐年一致性 8/8→5/8,样本外挑参收益直接归零——原结论被推翻,AP 退回默认档。
- **单边行情里,「谁赚得多」测的是方向暴露不是本事**(2026-08-19,生猪立项)。
  生猪三年单边熊市,一直挂空单就赚钱,累计盈亏榜前八全是净空席位。把「恒定仓位
  能赚到的钱」扣掉才看得见择时:运营者点名的永安期货 9.99 亿里只有 0.92 亿是择时
  (91% 是方向暴露),而平均只挂 227 手的东证期货 6.42 亿里有 5.40 亿。
  **验证方式很简单**:把这家的净持仓换成它自己的均值(仓位大小方向都不变)再算一遍,
  差额才是本事。同一段样本外实测:按 alpha 选 t=5.22、按总盈亏选 t=3.57、
  按仓位规模选 **t=0.11**。挑人之前先问「这个排名扣掉 beta 还剩什么」。
- **同一套方法换个品种可能整个反过来**(2026-08-19)。金银是「逐家席位算权重 ×
  多席位共振」,照搬到生猪会失败——生猪单家事件整体胜率只有 50%,而**八家合计的
  流向** t=5.4~7.5。品种的市场结构不同(生猪是产业套保 vs 散户,金银是投机资金),
  信号该聚合到哪一层就不同。**移植策略时先验证信号形态,不要只调参数。**
- **跨月合约的持仓变化,拆到合约层面会被移仓撕成相反的两半**(2026-08-19)。
  生猪逐合约信号 IC_t 只有 0.58,品种合计 t=5.22。查实:**84.6% 的交易日里同日
  不同合约的信号方向相反**,`|合计净变化|/Σ|各合约变化|` 中位数仅 0.62。机构看空的
  是品种,执行时分散在几个合约上;从近月移到远月,单看近月是「减空」远月是「加空」,
  方向一步没变。**「合约价差大」影响的是计价(必须逐合约),不是方向信号(该用品种
  合计)——两件事分开想。**
- **做空的复利收益不是买入持有取反**(2026-08-19,差点把基准写错)。价格跌 52.9%,
  恒定满仓做空的复利收益是 **+99.2%** 不是 +52.9%。用错基准会把「跑赢躺着不动」
  说成两倍于实际的优势。算基准就老老实实逐日累乘 `(1 − ret)`。
- **「跟随机构方向」要分清「减仓」和「转向」**(2026-08-19,生猪做多支路)。
  生猪信号 z>0 只表示机构**在减空**,不表示**转多**——15 笔做多进场当日,机构合计
  净持仓全部仍是负的(−28,284 ~ −974 手)。把「不那么看空了」当成「看多了」跟进去,
  三年逐笔累计 −1.5%、均值 −0.02%,纯属抛硬币。**先问信号的绝对水平在哪一侧,
  再看它的变化方向。**
- **一个事件里的 14 个交易日不是 14 个样本**(2026-08-19)。查「机构真转多之后
  会不会涨」,样本里净持仓转正共 14 天——但它们全挤在 2025-07 一个窗口里,实质
  只有**一个事件**。这种样本能得出的结论只有「没有证据支持」,不能是「证明了会跌」。
  报数时要把窗口分布写出来,只报 N=14 是在夸大证据强度。
- **同一个统计换个筛选口径可能整个翻掉**(2026-08-19)。DEC-083 写「机构一天都没
  转成净多、穿越零轴 0 次」——那是按**总盈亏**选的八家;换成按 **alpha** 选的五家,
  就有 14 天净多。**结论要连着「用哪组数据算的」一起写**,否则下一轮换了口径,
  旧结论会被当成事实继续引用。
- **全样本显著不等于稳定有效,要逐年看符号**(2026-08-19,玻璃)。玻璃合计流向全样本
  t=+2.96 看着能用,拆到逐年是 **7 年正、7 年负**——那个显著性是被 2019~2022 一段
  单独撑起来的。生猪同样的检验是 4 年全正。**报一个因子之前,先把逐年符号列出来数
  一遍**:符号一半一半的因子,再高的全样本 t 也是拼出来的。
- **别人质疑是不是方法没用对时,要把替代解释真的测掉再回答**(2026-08-19)。
  运营者提出玻璃跟着地产走、有牛熊,怀疑是市况没分对。这个替代解释很合理,不能靠
  嘴否掉——按 MA120、MA250、过去 60 日涨跌三种分法各测一遍(全部同号、不反向),
  结论才站得住。**测一次的成本,远低于把一个错误结论写进决策记录。**
- **回放口径 ≠ 实盘记录**:历史 ⚡ 是"当时按今天规则会怎么标",不是当时真实
  报过的信号;统计盘后算,执行等于次日。
- **环形日历轴上「起点参差」伪装成「终点越界」**:叠年图先查各年窗口起止对齐。
- **写端点对拍要比落库字节**,响应一致不代表存的一样(充值码写库回空 body 案例,
  shejimao 侧教训,通用)。

## 七、判断与流程

- **缓存失效该由「数据变了」驱动,不是由时间驱动**(2026-08-18,运营者纠正
  我的第一版方案):报告表十几秒的重算,我先做成「TTL 延长 + 定时重算」,
  两头都错——空闲时段反复重算一模一样的东西,到点失效又让人再撞一次。
  正解是拿数据版本(相关表的 `max(updated_at)`)当缓存键,没变就永远命中。
  **贵的计算前面要问的是「它依赖的东西变了没有」,不是「过了多久」。**

- **"影响面很大"的结论要先自查验证路径**(见四·「(代客)」事件)。
- **约束拦住的值,先判断它是真实还是脏数据,再决定放宽还是修数据**
  (2026-08-18 反面案例):回填撞 sane 护栏,我查到历史低点 −8020 就判定
  「真实观测,百分位区间被撑爆」并放宽了护栏;实际那天收盘价是 0,是脏数据,
  **护栏本来是对的**。看到异常值先查它的原始行(是不是 0/NULL/单位错),
  查完再动守卫——放宽守卫是最后手段,不是第一反应。
- **污染会话的交接结论要重验**再采信。
- **改引擎/采集 SQL 的部署后必须手动重跑重算**,并核对产物(列非 NULL、
  行数、抽样值);重算窗口:日常 45 天,动了历年口径用 5000 天全量
  (约 20-40 分钟,anchor_row 是大头,nohup + 轮询)。

- **同一个数字在两个页面对不上,先查两条取数路径的时序**(2026-08-18):
  高盛 08-17 掉榜,报告表算得出 2,334 手,净持仓页一片空白。两处都对——报告表
  走**读时**反推,净持仓页读**库里**的反推行,而写反推行的脚本挂在 collector
  里(16:00),官方席位却要等 16:25 的另一条链才入库。反推的依据是回榜日的
  增减量,拿不到回榜行就整段推不出来,官方源品种因此永远滞后一整轮
  (实证:大商所席位由 collector 自采,反推到 08-17;上期所郑商所停在 08-14)。
  **一条流水线上,写数据的步骤排在读数据的步骤后面,不会报错,只会静默地
  少算一轮。**加派生步骤时要问的是「它依赖的行,这一刻真的已经在库里了吗」。

- **测试 mock 缺字段不是「写简单点」,是让组件在渲染期读到 undefined**
  (2026-08-18):给净持仓页加了个读 `day.inferred_members.length` 的
  computed,mock 里没这个字段,于是三个 unhandled rejection——而
  **74 个断言全绿、`Test Files 13 passed`,只有进程退出码是 1**。
  按接口补齐 mock,不要在生产代码里加 `?? []` 去迁就 mock:那是拿真实路径的
  防御性代码掩盖测试数据的缺陷。收工看的是退出码,不是那行绿字。

- **「加个功能」与「这个功能该长在哪」是两件事**(2026-08-18,运营者两次纠正
  同一个页面):净持仓要的是多席位合计 + 收藏,我做成了**独立页面**,还特意把

- **部署卡在「Deploy, migrate, and run VPS acceptance」不代表没部署成功**
  (2026-08-18,一轮跑了 16 分钟 vs 平常 3~4 分钟):远端脚本早就做完并切换了,
  拖的是 GitHub 那边 SSH 会话收尾。**判据在服务器上,不在 Actions 页面**——
  查 `stable.env` 的 `previous_git_sha`、发布目录名带的 run id、容器 Up 时长、

- **「先挑一行再检查合不合格」会让残缺行顶掉完整行**(2026-08-19,品种汇总 K 线
  缺三天):`distinct on` 按源优先级挑出唯一一行,过滤却排在它下游——同一天同一
  合约既有残缺的高优先级行、又有完整的低优先级行时,挑中前者、过滤掉,那格数据
  就凭空没了,而好数据就在旁边。**完整性/有效性过滤必须排在 `distinct on` 的
  同一个 select 的 where 里,不能等挑完再筛。**旁证很关键:同一份逻辑的单合约版
  (`load_contract_candles`)是先过滤再挑,从没出过这问题——两处写法不一致本身
  就是信号。查一个「某天数据没了」的 bug,先看数据在不在库(在),再看取数管线
  哪一步把它丢了(这一步)。
- **换行布局里,靠「相邻兄弟选择器」做的分隔符会把行首元素顶歪**(2026-08-19)。

- **组件搬家漏带 prop,功能静默消失**(2026-08-19):净持仓四张图从独立页面搬进
  席位页时漏了 `group`,ECharts 的 dataZoom 联动就没了——不报错,只是各缩放各的。
  **搬一组组件时,把它原来带的每个 prop 都对一遍**,尤其是那种「少了也能跑、只是
  少个行为」的(group / connect / 事件绑定)。这类回归编译测试都抓不到,只有肉眼

- **单测全绿也挡不住「组件库在真实输入下根本不调你的回调」**(2026-08-19,拼音
  搜索)。`pinyin.test.ts` 逐条验过 `gs`→高盛,而页面上输入 gs 什么都不出来——坏的
  不是拼音表,是事件链路:el-select 的 `handleQueryChange` 头一行
  `if (… || isComposing.value) return`,中文输入法预编辑期间**整个跳过 filter-method**。
  那条短路为「打中文」而设(敲拼音先别搜,选完字再搜),可这个搜索框的主力用法恰恰是
  **永远不选字**,composition 永不结束,查询永远是空串。
  **纯函数的测试只证明纯函数对**;功能要挂真实组件、按真实输入方式(含输入法)走一遍
  才算验过。定位手法值得记:写一个隔离 harness 对拍两种输入路径,一次就把「拼音表坏了」
  和「事件没传到」分开了。
- **两个各自合理的设计能凑出一个谁都没想要的死角**(2026-08-19,清空席位后搜不了)。
  「加载期间禁用输入」合理,「一家不剩就自动补一家」也合理(它防的是空表看不出
  是坏了还是没数据),两个凑一起:清空即进 loading 变灰不能输入,加载完又被塞回一家,

  「我要重挑」,不是「出错了」——**需求变形态时,回头看看老兜底还成不成立**。
