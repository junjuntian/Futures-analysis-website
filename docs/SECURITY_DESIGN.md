# 安全设计

## 1. 安全目标

- 防止未授权读取或修改业务数据。
- 防止通过主键、缓存、任务、文件对象、采集批次或 AI 工具跨 Workspace 访问数据。
- 防止采集器、任意 URL 和文件解析能力访问宿主机或内网。
- 防止密码、Cookie、AI Key 和主密钥泄漏。
- 防止不可信文件、网页和 AI 内容改变系统策略。
- 保证审计、备份和恢复过程不破坏机密性与可追溯性。

## 2. 信任边界

| 边界 | 不可信输入 |
| --- | --- |
| 浏览器 → API | 请求参数、Cookie、上传文件、富文本 |
| Session → Workspace | 伪造的 `workspace_id`、跨 Workspace 资源标识 |
| API/Worker → PostgreSQL | 动态过滤、批量数据、任务载荷 |
| 调度器 → collector | 数据源、交易日期、回填范围、任务参数 |
| collector → 交易所公开接口 | 响应正文、公开文件、重定向、错误页 |
| collector → 导入 API | 标准化 CSV、固定模板版本、来源与采集任务元数据 |
| AI Gateway → 外部模型 | 用户文本、网页内容、工具结果、模型输出 |
| 本地存储 | 文件名、MIME、压缩包、SVG、对象引用 |

## 3. 身份与 Session

- 密码使用 Argon2id；参数基于部署机器基准确定并版本化。
- 登录成功后生成高熵 session token，数据库只保存 token 哈希。
- 登录、权限变化和密码修改后轮换 session，防止 session fixation。
- Cookie 设置 `Secure`、`HttpOnly`、合适的 `SameSite`、最小 `Path`，生产环境禁止明文 HTTP。
- 有副作用的请求校验 CSRF token 和 `Origin`/`Referer`。
- session 具有绝对有效期、空闲有效期、撤销和并发 session 策略。
- 登录、CSRF、权限拒绝和高风险操作实施限流并记录安全事件。
- 首个管理员通过 `BOOTSTRAP_TOKEN` 一次性初始化流程创建；首个用户创建成功后初始化入口永久关闭。密码重置和可选 MFA 策略仍待后续确认。
- 登录成功后服务端解析用户唯一的个人 Workspace，生成不可由客户端覆盖的 `WorkspaceContext`。

## 4. 权限

- API 在应用用例入口校验权限，不依赖前端隐藏按钮。
- 查询、写入、后台任务、对象存储、采集批次和缓存必须按 `workspace_id` 强制过滤。
- 所有业务唯一约束包含 `workspace_id`；资源主键存在但不属于当前 Workspace 时按不可见处理。
- AI 工具复用相同权限策略，不另建“超级只读账号”。
- 管理密钥、回滚、权限变更和导出敏感数据需要更高权限和二次确认。
- MVP 中业务数据归属于个人 Workspace，不直接归属于创建数据的 User；不提供共享或邀请。
- 系统 `admin` 权限不隐含跨 Workspace 业务数据读取；用户管理与业务数据授权必须分开。

## 5. SSRF 与采集容器出口约束

应用层校验：

- 不开放任意 URL；只接受已配置的五交易所 `data_source_id` 和对应 akshare 连接器操作。
- 连接器域名必须命中 DCE、SHFE、CZCE、GFEX、CFFEX 的服务端白名单；东方财富等二手数据源不进入第一批。
- 解析主机后拒绝 loopback、私网、链路本地、保留地址、IPv4 映射 IPv6 和云元数据地址。
- 每次重定向重新校验协议、主机和 IP；限制跳转次数、响应大小、下载大小、超时和并发。

网络层强制：

- akshare 采集器运行在独立低权限 Python 容器，按需拉起、跑完退出；根文件系统只读，无宿主机目录挂载。
- 采集容器仅允许访问交易所域名白名单；出口代理或防火墙执行域名/IP 策略，不能只靠应用检查。
- 禁止访问 Docker socket、数据库、对象存储、平台管理端口和云元数据；采集结果只通过导入 API 提交。
- 防 DNS Rebinding：解析前后检查，连接目标与校验结果绑定。

## 6. 文件与解析安全

- 校验扩展名、MIME、magic bytes 和实际容器格式。
- 限制文件大小、解压后大小、压缩比、工作表数、行列数、单元格长度和解析时间。
- 解析器使用流式/有界内存；超限安全终止。
- 不执行宏、外部链接、DDE、嵌入对象或公式。
- 保存原始公式文本时按不可信内容处理；导出 CSV 时防公式注入。
- 用户文件名仅作显示，落盘使用随机 `object_key`。
- 上传对象先进入隔离区，校验完成后才可进入导入流程。
- SVG 输出移除脚本、外部引用、事件属性和危险 URL，下载时使用安全响应头。

## 7. 密钥与信封加密

- 密码只存哈希；AI API Key 等敏感配置使用带认证的信封加密。
- 每条或每组敏感数据由 DEK 加密；数据库只保存 `ciphertext`、`wrapped_dek`、`kek_version`、`nonce` 和算法元数据。
- 主密钥/KEK 不进入数据库、代码仓库、Docker 镜像、普通日志或 Git。
- futures VPS 当前主密钥文件为 `/etc/futures-platform/secrets/master-key-v1`，由 `root` 所有，权限 `0400`，只读挂载给需要解密的容器。
- 主密钥必须版本化；轮换通过新版本 KEK 重新包裹 DEK，不要求解密并重写全部业务明文。
- 解密前校验当前 `workspace_id`、用途和密文所有者，避免密文复制造成跨 Workspace 解密。
- 前端保存后不再读取完整密钥，只显示掩码和元数据。
- 错误、Tracing span、审计 `before_json/after_json` 和工具参数统一脱敏。
- 数据库备份与主密钥恢复副本分开保存；两者使用不同访问控制和保管位置。
- 主密钥恢复副本的保管人、轮换周期和线下审批流程仍需在部署设计阶段确认。

## 8. AI 安全

- 自动采集内容、导入文件、笔记和模型输出均是不可信数据。
- 系统提示与工具策略固定在服务端；检索内容不得声明或修改工具权限。
- 工具使用严格 JSON schema、参数白名单、最大日期范围和最大返回行数。
- 工具结果按 `WorkspaceContext` 和权限过滤并附来源，不允许通用 SQL 工具或任意代码执行。
- 模型无写工具；所有写请求即使由文本诱导也拒绝。
- 对外发送前实施数据最小化、敏感字段过滤和用户可见提示。
- 记录提供商、模型、区域、保留政策和用量；不得把 API Key 写入提示。

## 9. 审计与日志

- 每个请求、任务、导入批次、计算批次使用关联 ID。
- 记录登录、权限、密钥、采集、导入、回滚、导出和 AI 工具事件。
- 审计追加写并限制修改权限；是否需要防篡改哈希链待风险评估。
- 日志不记录完整请求体、上传内容、Cookie、Authorization、API Key 或数据库连接串。
- 定义日志、审计和 AI 对话保留期，到期执行可验证清理。

## 10. 备份与恢复

- PostgreSQL 与对象文件使用一致的恢复点或记录可重建顺序。
- 备份加密，密钥与备份分离保管。
- 数据库备份和主密钥恢复副本必须分开保存，单一备份介质不得同时包含二者。
- 恢复演练验证数据库、对象引用、`kek_version`、Workspace 隔离、权限和审计完整性。
- RPO、RTO、保留周期和异地位置待确认。

## 11. 上线安全门槛

- 完成威胁模型和权限矩阵评审。
- CSRF、SSRF、上传炸弹、路径穿越、越权、提示词注入和密钥泄漏测试通过。
- 跨 Workspace 的 UUID/BIGINT、任务、对象键、采集批次和 AI 工具访问测试全部被拒绝。
- 所有严重/高危依赖漏洞已处理或有批准的风险接受记录。
- 生产 Cookie、TLS、CORS、CSP、HSTS 和安全响应头配置验证通过。
- 备份恢复演练成功。
