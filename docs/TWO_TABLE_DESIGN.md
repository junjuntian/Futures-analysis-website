# 两张表：品种历史价格、席位持仓

运营者 2026-08-10 定：数据分两部分，**品种历史价格**与**席位**。
本文是「先采、再分析、**再建表**、最后灌」的第三步，依据是 `RAW_FIELD_INVENTORY.md`
里实际取到的文件，不是推想。

设计的唯一目标是运营者提的那句话：**数据库要很容易看，不要弄得很乱**。
所以两张表都做成「一行就是一个事实」，看一眼就知道是什么，不需要先读代码。

## 表一：品种历史价格

**一行 = 一个合约在一个交易日的行情。**

| 列 | 含义 | 说明 |
| --- | --- | --- |
| `exchange` | 交易所 | DCE / CZCE / SHFE |
| `instrument` | 品种 | JM JD LH AP FG SA AU AG |
| `contract` | 合约 | **统一大写 + 四位月份**：`AP2501`、`JM1601`、`AU2412` |
| `trade_date` | 交易日 | |
| `open` `high` `low` `close` | 开 高 低 收 | 当日无成交时四项皆空，不写 0 |
| `settlement` | 结算价 | 席位成本用它 |
| `prev_settlement` | 前结算价 | 三家都给，留着便于对账 |
| `volume` | 成交量（手） | **不换算**，见下 |
| `volume_basis` | 成交量口径 | `double` 双边 / `single` 单边 |
| `turnover` | 成交额（**元**） | **统一换算为元**，见下 |
| `open_interest` | 持仓量 | |
| `open_interest_change` | 持仓变化 | 大商所 2019 起不给，留空 |
| `source` | 来源 | `dce_official_history` / `czce_official` / `shfe_official` |

### 三条必须显式处理的差异

1. **成交额统一换算为元。** 大商所给的是元，郑商所与上期所给的是**万元**。
   入库时后两家 ×10000。不换算的话同一列里两种量纲，任何跨交易所的比较和
   「成交额 ÷(成交量 × 结算价) = 点值」这条校验都会失效。
2. **成交量不换算，只如实记录口径。** 大商所双边、郑商所 2020 年起单边。
   除以二看起来能对齐，但那是我们编的数，不是交易所公布的数。
   记 `volume_basis`，让算的人自己决定怎么用。
3. **合约代码归一为大写四位月份。** 郑商所发的是 `AP501`（三位月份），
   世纪按该品种上市年份推——苹果 2017 年上市，所以 `501` 只可能是 2025 年 1 月。
   不能按「大于当前年份就减 100」这类规则猜。

## 表二：席位持仓

**一行 = 某个会员、在某个合约（或某品种汇总）、在某个榜单上、某一天的一条排名。**

| 列 | 含义 | 说明 |
| --- | --- | --- |
| `exchange` | 交易所 | |
| `instrument` | 品种 | |
| `contract` | 合约 | 品种汇总行为空 |
| `is_variety_total` | 是否品种汇总 | 见下 |
| `trade_date` | 交易日 | |
| `rank_type` | 榜单 | `volume` 成交量 / `long` 持买 / `short` 持卖 |
| `rank` | 名次 | 交易所只公布前 20，这是上限不是我们的截断 |
| `member` | 会员简称 | |
| `quantity` | 手数 | 该榜对应的量 |
| `change` | 较前一日增减 | 三家都给 |
| `source` | 来源 | `czce_official` / `shfe_official` / `sanhe` / `eastmoney` |

### 为什么要 `is_variety_total`

运营者要求建仓过程除按合约外，**还要一个品种汇总**，理由是单合约会因掉出前 20 而中断。

- **上期所自己就发品种汇总行**（`INSTRUMENTID` = `cuall` 这类），
  **郑商所也发**（段落标题是「品种：苹果AP」而不是「合约：AP501」）。
  这两家直接照收，标 `is_variety_total = true`。
- 交易所自己算的汇总与我们把各合约加总**未必相等**（各合约前 20 的并集不等于品种前 20）。
  能拿到官方的就用官方的，拿不到的再自己算，并且要能分辨这一行是哪来的。

### 三家的形状差异如何落到同一张表

| | 原始形状 | 转换 |
| --- | --- | --- |
| 郑商所 | 分段文本，一行里**三对（会员，数量）**，分属三个榜 | 拆成 3 行，各带自己的 `rank_type` |
| 上期所 | `o_cursor` 数组，`PARTICIPANTABBR1/2/3` + `CJ1/2/3` | 同上，拆成 3 行 |
| 三禾（大商所） | 按**会员**给，一次返回该会员全部品种的 `buy`/`ss` | 转置：每个（会员，合约）拆成 `long` 与 `short` 两行 |

**三禾没有名次和成交量榜。** 它给的是持买、持卖两个数，不给 `rank`，也不给成交量榜。
所以大商所三个品种的席位行 `rank` 为空、`rank_type` 只有 `long` 与 `short`。
这是来源的限制，如实留空，不编造名次。
