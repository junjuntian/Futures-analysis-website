# 分阶段开发计划

## 1. 执行原则

- 每阶段只交付已定义范围，不提前实现后续模块。
- 进入阶段前，相关 P0 待确认事项必须关闭。
- 每个阶段必须同时交付功能、迁移、测试、OpenAPI、运维说明和验收证据。
- 数据口径优先于页面效果；安全边界优先于自动化程度。
- 当前已获准进入阶段 1；阶段 1 仅实现工程基础，不实现正式业务页面或业务算法。

## 1.1 多环境职责与独立审查

- 本地 Git 是唯一源码源头，所有源码修改、最终差异核验和提交均以本地 Git 工作区为准。
- Codex Cloud 可用于独立代码审查、编译和单元测试、静态分析和安全扫描，以及与本地环境无关的并行开发任务。
- 使用 Codex Cloud 必须满足以下前提：
  - 项目已推送到 GitHub 私有仓库。
  - 不上传生产密钥、Cookie、数据库备份或用户数据。
  - 云端结果必须回到本地 Git 重新核验。
  - 云端测试不能代替 `futures` VPS 的 Docker、数据库、RLS、文件持久化和真实部署验收。
- 环境职责固定为：
  - 本地 Git：唯一源码源头。
  - Codex Cloud：辅助开发、测试和独立审查。
  - `futures` VPS：最终构建、迁移、E2E 和部署验收。
- 子 Agent 连续两次卡住时：
  - Generator 可改用新的顶层 Codex 会话接管。
  - Evaluator 可改用新的顶层 Codex 会话或 Codex Cloud 独立审查。
  - 主 Agent 不得冒充独立 Evaluator。

## 2. 阶段 0：分析与文档基线

目标：把 Word 方案转换为可执行、可评审的开发基线。

交付物：

- 根目录项目说明、开发规则和状态计划。
- 产品、架构、模块、数据库、API、安全、导入、AI 设计。
- 已确认决策记录及其跨文档一致性。
- 开发计划、验收标准和待确认事项。
- 原始 Word 方案的未修改副本和哈希。

验收：

- 所有要求文件存在且使用中文。
- 代码/API/字段名称使用英文。
- 技术冲突、缺失需求、安全风险和未确认决策有明确归属。
- 无业务代码、依赖安装或数据库创建。

退出条件：项目所有者确认剩余阻断事项，且 `DECISIONS.md`、数据模型和验收标准完成评审后冻结 MVP 范围。

## 3. 阶段 1：工程基础、身份与审计

前置：反向代理、首个管理员初始化、主密钥具体载体、RLS、SSE/noVNC 参数已确认；Phase 0 文档审查无未处理 BLOCKER/HIGH。

交付物：

- Rust Workspace、Vue 工程、pnpm 锁文件、`rust-toolchain.toml`。
- Axum API、Worker 生命周期、配置加载、Tracing 和统一错误。
- PostgreSQL 基础迁移、SQLx 离线元数据策略和测试数据库流程。
- 用户、个人 Workspace、Cookie Session、CSRF、Workspace 强制隔离和审计。
- 应用层 UUIDv7、BIGINT identity 分类及确定的金融 `numeric` 类型。
- 信封加密端口、`wrapped_dek`/`kek_version` 元数据和主密钥注入边界。
- Docker Compose 开发环境和 OpenAPI 骨架。

验收：

- 当前稳定 Rust 版本被固定且可重复构建。
- 登录、退出、session 轮换、撤销和权限拒绝测试通过。
- CSRF 与越权测试通过。
- 任意跨 Workspace 的业务主键、任务或对象引用均被拒绝。
- API 和 Worker 可独立启动、优雅关闭。
- OpenAPI 与实现契约一致。

## 4. 阶段 2：基础目录、对象存储与导入中心

前置：文件容量限制、交易所日历初始来源和主密钥测试方案确认。

交付物：

- `catalog`、`storage`、`import`、`jobs` 模块。
- 本地 `ObjectStorage` 适配器。
- TXT、CSV、XLS、XLSX 识别、映射、预览、校验和提交。
- UTC/`trade_date`/`session_type`、收盘价/结算价和 CNY 精度映射。
- PostgreSQL 任务租约、心跳、重试、幂等和死信。
- 导入变更日志、回滚和报告。

验收：

- 三种以上真实格式样例导入成功，包含中文编码和 Excel。
- 重复提交不产生重复正式数据。
- 无后续修改或依赖的批次可整批原子回滚。
- 存在后续修改或依赖时整批零变更并返回冲突；补偿批次可追溯，不支持部分回滚。
- 大文件/异常文件在资源限制内安全失败。
- 任一记录可追溯到文件、行号、映射版本和批次。

## 5. 阶段 3：多腿套利与图表

前置：腿对齐、缺失值、情景计算输入和统计算法细节确认。

交付物：

- 多腿定义、公式版本、计算批次和来源下钻。
- `price_basis`、交易日历版本、外部连续合约来源和换月规则元数据。
- 描述统计、百分位、Z-Score、季节性和路径统计。
- ECharts 查询模型、正负分段、PNG/SVG 导出。
- 独立受限的图表渲染沙箱。

验收：

- 固定样例的价差和统计与人工/参考实现完全一致或在批准误差内。
- 公式版本变化不静默覆盖历史结果。
- 行情图默认收盘价，所有结果显示价格口径；MVP 不生成连续合约或运行历史回测。
- 缺失腿和非同步日期产生明确质量状态。
- 正红负绿过零插值正确，PNG/SVG 通过视觉与安全测试。

## 6. 阶段 4：成交、持仓与绩效

前置：平今/平昨、双向持仓展示和具体手续费参数来源确认。

交付物：

- 账户、成交、交易组、持仓快照、每日权益。
- 不可覆盖的原始成交、FIFO 配对分配和冲销/补偿记录。
- 已实现/未实现盈亏、胜率、盈亏比、期望收益、Profit Factor、最大回撤。
- 录入、导入、查询和绩效页面。

验收：

- 人工样本覆盖部分平仓、手续费、跨日和套利交易组。
- 每个统计值可下钻到成交或权益数据。
- 仅完整交易组进入胜率。
- 已实现净盈亏使用实际成交价并包含手续费；未实现盈亏和权益默认使用结算价。
- 持仓快照不会被误用于推导无法确定的成交胜率。

## 7. 阶段 5：席位分析

前置：席位来源、别名治理和分类证据标准确认。

交付物：

- 席位导入、标准化、别名和有效期。
- 分类版本、证据、可信度。
- 前 5/10/20、集中度、净持仓、变化和背离。

验收：

- 同一别名在不同来源和有效期内正确解析。
- 分类变化不改写历史版本。
- 任一汇总值可下钻到原始席位行。
- UI 不把倾向分类表述为最终投资者事实。

## 8. 阶段 6：授权网页采集与 OCR

前置：首批交易所端点、采集频率、noVNC 短期 token 参数和 OCR 部署规格确认。

交付物：

- 隔离 Chromium、Playwright、noVNC、网络出口策略和信封加密 session。
- Workspace/数据源独立 Browser Context。
- 至少一个交易所公开数据源连接器；不开放任意 URL。
- 原始快照、结构化提取预览和人工确认。
- OCR 服务、置信度、人工校对。

验收：

- SSRF、DNS Rebinding、重定向、子资源和下载测试通过。
- noVNC 未直接暴露，跨 Workspace/数据源 Context 与登录状态访问被拒绝。
- 页面规则变化只修改连接器。
- 用户凭据不进入 API 日志或应用表单。
- OCR 未确认数据不能进入正式表。
- 站点授权、白名单和频率限制有记录；三禾连接器在授权确认前不可启用。

## 9. 阶段 7：AI 分析

前置：Provider、数据出境/保留、费用预算和对话保留策略确认。

交付物：

- 多 Provider 能力适配和加密密钥。
- 只读工具、来源包、提示模板版本和用量统计。
- 提示词注入防护和固定评估集。
- 对话页面和审计。

验收：

- 数值与工具结果一致。
- 回答包含截止日期、样本范围、排除规则和来源。
- 越权、写操作、通用 SQL 和秘密请求被拒绝。
- Provider 降级、超时、限流和费用限制可验证。

## 10. 阶段 8：自动化、运维与上线加固

前置：容量、RPO、RTO、保留期和告警渠道确认。

交付物：

- 定时更新、报告和提醒。
- 指标、告警、备份、恢复演练和运行手册。
- 性能、负载、安全和灾备测试。
- 发布、回滚和数据迁移流程。

验收：

- 任务重试和幂等不重复写入。
- 备份可恢复数据库、对象和密钥版本。
- 容量和延迟达到批准目标。
- 高危安全问题清零或有正式风险接受。

## 11. 暂缓项

以下能力必须单独立项，不因上述阶段完成而自动进入：

- 完整策略回测。
- 分钟级行情和 TimescaleDB。
- 多租户 SaaS。
- 移动端/PWA。
- 自动交易和交易账户连接。
