## 1. 执行原则

- 每阶段只交付已定义范围，不提前实现后续模块。
- 进入阶段前，相关 P0 待确认事项必须关闭。
- 每个阶段必须同时交付功能、迁移、测试、OpenAPI、运维说明和验收证据。
- 数据口径优先于页面效果；安全边界优先于自动化程度。
- Phase 1 至 Phase 3 已完成；Phase 4 及后续阶段仍须分别建立 Planner 契约并获得实施授权。

## 1.1 多环境职责与独立审查

- 本地 Git 是唯一源码源头，所有源码修改、最终差异核验和提交均以本地 Git 工作区为准。
- Codex Cloud 可用于独立代码审查、编译和单元测试、静态分析和安全扫描，以及与本地环境无关的并行开发任务。
- 使用 Codex Cloud 必须满足以下前提：
  - 项目已推送到 GitHub 私有仓库。
  - 不上传生产密钥、Cookie、数据库备份或用户数据。
  - 云端结果必须回到本地 Git 重新核验。
  - 云端测试不能代替 `futures` VPS 的 Docker、数据库、RLS、文件持久化和真实部署验收。
- 环境职责固定为：
  - 本地 Git：唯一源码源头。
  - Codex Cloud：辅助开发、测试和独立审查。
  - `futures` VPS：拉取已验证镜像、执行迁移、E2E 和部署验收，不承担常规编译。
- 子 Agent 连续两次卡住时：
  - Generator 可改用新的顶层 Codex 会话接管。
  - Evaluator 可改用新的顶层 Codex 会话或 Codex Cloud 独立审查。
  - 主 Agent 不得冒充独立 Evaluator。

## 4. 阶段 2：基础目录、对象存储与导入中心

前置：文件容量限制、交易所日历初始来源和主密钥测试方案确认。

交付物：

- `catalog`、`storage`、`import`、`jobs` 模块。

- PostgreSQL 任务租约、心跳、重试、幂等和死信。

验收：

- 三种以上真实格式样例导入成功，包含中文编码和 Excel。
- 重复提交不产生重复正式数据。
- 无后续修改或依赖的批次可整批原子回滚。
- 存在后续修改或依赖时整批零变更并返回冲突；补偿批次可追溯，不支持部分回滚。
- 大文件/异常文件在资源限制内安全失败。
- 任一记录可追溯到文件、行号、映射版本和批次。

## 5. Phase 4：akshare 采集与全历史回填

前置：`DEC-025`、`DEC-031`、`DEC-038`、`DEC-039` 已确认；五交易所白名单、固定映射模板和导入 API 契约完成详细设计。

交付物：

- 独立 Python akshare 采集器容器；每交易日盘后由调度按需拉起，跑完退出，不常驻。
- 一次覆盖 DCE、SHFE、CZCE、GFEX、CFFEX，经 akshare 拉取交易所公开接口与公开文件；东方财富按 `DEC-043` 承担席位兜底（排在全部官方源之后），并按 `DEC-045` 承担大商所的行情与合约目录——大商所官方接口自 2026-08-02 起全线 412，`DEC-041` 当初选的新浪兜底对其在市合约只覆盖 44%，两者均已退役，其余二手数据源不进入第一批。（该源无 akshare 函数，由采集器自有客户端直连，受同一套域名白名单与 DNS 围栏约束。）
- 产出标准化 CSV 后调用平台导入 API，保留来源、批次、变更日志和整批回滚机制。
- 白名单自动采集批次使用固定映射模板版本，免人工确认、免提取预览，直接进入正式表；手动文件导入流程不变。
- 全市场日行情（收盘价与结算价）、全市场席位龙虎榜（各合约成交量、持买、持卖排名）、交易日历和合约参数。
- 全部可得历史回填：行情全量一次拉取；席位先近 5 年，再由后台任务倒序向更早年份补拉；不可得年份留记录、不阻塞。

验收：

- 采集容器仅访问五交易所白名单域名，不能访问内网、宿主机管理面或非白名单数据源。
- 解析或校验失败的批次自动隔离为 `failed` 且正式表零写入；质量警告记录但不拦截。
- 重试和断点续跑不重复入库，来源、任务、标准化 CSV、导入批次和正式记录可追溯。
- 成功批次满足 Phase 3 已实现的整批回滚契约。
- 席位历史按近 5 年优先、逐年向前补拉；不可得年份有明确记录且不阻塞其他年份。
- 磁盘达到 80% 水位时扩容 VPS 磁盘，不更换机器。

## 6. Phase 5：套利分析与图表

状态：5A 实施后期（2026-08-11）。自由价差已切**自建价差引擎**（`DEC-046`，三禾降为
可回退备选）；大商所行情日更改走新浪（`DEC-047`）；席位两页（席位持仓/建仓过程）与
会员跨源归一已随 5A 上线。5A 收口前不实施 5B。详细唯一实施契约见
`docs/phases/PHASE_05_SPREAD_ANALYTICS.md`。

前置：`DEC-042`、散户可交易窗口、腿对齐、缺失值和统计算法细节已经契约化并获用户确认。

交付物：

- 5A 先交付自由价差：三禾三个只读 POST 接口由 Rust 服务端代理，以
  `SpreadSeriesProvider`、至少 1.5 秒限频、同参数当日持久缓存和稳定错误隔离上游。
- 三禾序列按实际合约代码和本库交割月裁剪散户可交易窗口；连续轴、季节图和月度矩阵
  由裁剪后序列在服务端重算，不使用三禾原始统计作为用户真值。
- 5B 随后交付自有库套利监控、表单式组合定义、详情页、多腿定义、公式版本、计算批次
  和原始腿来源下钻；统计窗口随自有数据积累。
- `price_basis`、交易日历版本、外部连续合约来源和换月规则元数据。
- 描述统计、经验分位、Z-Score、季节性、月度矩阵和路径统计。
- ECharts 查询模型、正负分段以及前端 PNG/SVG 导出。
- SVG 安全清洗与安全下载。

验收：

- 5A 与 5B 各自通过独立 Evaluator 门禁；5A 收口后才开始 5B。
- 固定样例的窗口截取、价差和统计与人工/参考实现完全一致或在批准误差内。
- 公式版本变化不静默覆盖历史结果。
- 自有行情图默认收盘价；三禾序列如实标为 `upstream_spread` 且声明无原始腿价格；
  所有结果显示真实数据来源、取数时间和口径。MVP 不生成连续合约或运行历史回测。
- 缺失腿和非同步日期产生明确质量状态。
- 正红负绿过零插值正确，PNG/SVG 通过视觉与安全测试。

## 10. Phase 10：机构资金（席位 Alpha）

状态：**进行中**（2026-08-11 经 `DEC-048` 进入总方案）。设计定稿见
`docs/SMART_MONEY_DESIGN.md`，离线研究在 `research/`（不走生产流程），已落地部分由
并行会话交付。

一句话定位：不是龙虎榜跟单，是「历史验证过的席位行为 × 持续建仓 × 多席位共振 ×
价格确认」的规则引擎。输入 = 两张历史表（`price_history`/`seat_history`），
**不新增采集源**。

里程碑与现状：

| 里程碑 | 内容 | 现状 |
| --- | --- | --- |
| M0 采数据 | 两张表灌满 | 行情八品种全史已齐；席位五品种全史已齐，焦煤/鸡蛋/生猪三禾补采中（2023-08 起） |
| M2 离线研究 | 回测与规则定稿 | **黄金 v1 完成**（`research/REPORT_AU_v1.md`，R4+MA200）；**金银八家双强组规则定稿** |
| M3 引擎 | 定稿规则进每日管线 | **金银已上线**：`engine/smart_money.py` 每日信号 + 主力跑路警报（金银比极端 + 机构集体空银） |
| M4 界面 | 机构资金页 | **已上线**，平台内渲染，侧栏入口 |
| 后续 | 其余品种 | 席位历史灌满后按同一协议评估；未过判定门的品种只上观察页、不上信号 |

红线（沿用设计稿第 3.4 节防假统计协议，缺一不可）：滚动训练/验证分离、holdout 同号
留任、掉榜=不可知不是 0、T+1 执行、换月不跨合约、先验席位不豁免统计检验。

验收：

- 每笔信号可回查明细：触发当时哪些席位、各自 Flow、指数值。
- 扣费后跑赢三件套基准（买入持有、20 日突破、Top20Net 合计因子）才认定席位 Alpha。
- 未过判定门的品种不上信号。
