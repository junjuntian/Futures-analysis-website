# 数据库设计

## 1. 设计状态

本文定义 PostgreSQL 逻辑模型、约束和数据生命周期，不创建数据库或迁移文件。Workspace 归属、主键策略、金融精度、时间和价格口径已按 `DECISIONS.md` 固定；分区阈值仍待容量验证。

## 2. 通用约定

- 表名、列名、索引名使用 `snake_case`。
- 所有业务表包含非空 `workspace_id`；业务唯一约束和主要查询索引必须包含 `workspace_id`。
- 时间点使用 `timestamptz` 并以 UTC 存储；业务时区为 `Asia/Shanghai`；交易日使用 `date`。
- 市场数据独立保存 `trade_date` 和 `session_type`；夜盘依据版本化交易所日历归入下一交易日。
- `price`、`spread` 使用 `numeric(20,8)`；`money`、`fee`、`pnl` 使用 `numeric(24,4)`；`ratio` 使用 `numeric(20,10)`；`lots` 使用 `bigint`。
- 金融数据禁止使用浮点数作为最终存储类型。
- 统计展示值可使用 `double precision`，但必须记录算法和误差边界。
- 普通业务实体由应用层生成 UUIDv7；高频时间序列和明细表使用 `bigint generated by default as identity`。
- 所有 Workspace 业务表从首次迁移创建时启用 RLS；业务事务使用 `SET LOCAL app.current_workspace_id = '<uuid>'`，同时 Repository 查询必须显式包含 `workspace_id`。
- 正式业务表包含 `created_at`、`updated_at`；需要软删除时增加 `deleted_at`。
- 需要乐观并发控制的资源包含 `row_version`。
- 来源数据包含可用的 `source_id`、`import_batch_id`、`extraction_job_id`、`created_by`；`extraction_job_id` 指向 `extraction_jobs.id`。
- 原始记录、公式、映射、分类和统计参数不原地静默改写，使用版本或修订记录。

## 12. 索引与分区原则

- 先为业务唯一键、外键、`workspace_id`、`trade_date`、`session_type`、`contract_id`、`source_id` 和任务领取条件建立索引。
- 业务唯一约束必须包含 `workspace_id`，防止跨 Workspace 冲突或旁路访问。
- 使用真实数据和 `EXPLAIN (ANALYZE, BUFFERS)` 决定复合索引顺序。
- MVP 不默认按年/月分区；分区会影响唯一约束、外键和回滚复杂度。
- 达到已确认的行数、查询延迟或维护窗口阈值后再提交分区 ADR。
- TimescaleDB 只在分钟级数据或 PostgreSQL 原生方案无法满足指标时评估。

## 13. 数据保留与删除

- 原始文件、采集任务、审计、AI 对话和 staging 数据的保留周期分别配置。
- 正式原始数据默认不物理删除；删除请求通过软删除和延迟清理执行。
- 对象删除前验证无数据库引用且超过保留期。
- 备份恢复必须验证 `kek_version`、对象完整性、Workspace 引用和数据库引用一致性。
- 数据库备份与主密钥恢复副本分开保存；主密钥材料不出现在数据库备份中。
