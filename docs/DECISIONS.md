## 3. Workspace 与租户隔离

### `DEC-013` Workspace 数据归属

状态：已确认。

- 业务数据归属于 `Workspace`，不直接归属于 `User`。
- MVP 中每个用户自动对应一个个人 Workspace。
- MVP 不实现 Workspace 共享、成员邀请和跨用户协作。
- 所有业务表必须包含 `workspace_id`，查询、唯一约束、审计、任务、对象存储和 AI 工具均以 `workspace_id` 作为强制隔离条件。
- `users`、认证 session 和系统级角色属于身份基础设施，不以 `workspace_id` 作为业务归属。
- 不允许由客户端自由指定可访问的 `workspace_id`；服务端从已认证 session 解析当前 Workspace。
- 系统管理员身份不自动授予跨 Workspace 业务数据读取权限。

影响：产品权限、数据库模型、API 查询、后台任务、文件对象、浏览器会话、AI 工具和验收标准。

## 4. 分析范围和时间口径

### `DEC-014` MVP 排除历史回测

状态：已确认。

- MVP 不实现规则驱动的历史回测、自动生成交易信号或模拟成交。
- MVP 只提供历史统计、季节性、百分位、极值、回撤和情景计算。
- 真实成交的胜率和盈亏统计不属于回测，但只能基于完整 `trade_group`。

### `DEC-015` 时间、交易日和交易日历

状态：已确认。

- 系统时间点统一以 UTC 和 PostgreSQL `timestamptz` 保存。
- 业务展示和默认业务时区为 `Asia/Shanghai`。
- 市场数据独立保存 `trade_date` 和 `session_type`。
- 夜盘按照对应交易所的交易日历归入下一交易日。
- 交易日历按交易所分别维护，具有版本号，并支持带审计的人工修正。
- 任何按日统计都必须记录所使用的交易日历版本。

## 5. 价格、合约和交易口径

### `DEC-016` 价格口径

状态：已确认。

- 收盘价 `close_price` 与结算价 `settlement_price` 分别保存。
- 行情图默认使用收盘价。
- 日终持仓、未实现盈亏和权益默认使用结算价。
- 已实现盈亏使用实际成交价。
- 价差、统计、图表、持仓和报告结果必须记录 `price_basis`。

### `DEC-017` 连续合约与换月

状态：已确认。

- MVP 不自动生成连续合约。
- 允许导入外部连续合约数据，但必须记录数据来源和换月规则。
- 后续内部换月规则必须版本化，并单独记录换月事件。
- 外部连续合约不得与实际交割合约数据混用或伪装成原始合约行情。

### `DEC-018` 成交、配对和盈亏

状态：已确认。

- 原始 `trade_fill` 不允许覆盖修改；纠错使用冲销/补偿记录并保留关联。
- 开平配对默认采用 FIFO。
- 加权平均仅用于展示当前持仓成本，不用于改写成交配对或已实现盈亏。
- 已实现净盈亏包含手续费。
- 胜率按已完成的完整 `trade_group` 计算，不按单笔成交计算。

## 6. 标识和数值类型

### `DEC-019` 主键策略

状态：已确认。

- 普通业务实体使用应用层生成的 UUIDv7。
- 高频时间序列和明细表使用 PostgreSQL `BIGINT GENERATED BY DEFAULT AS IDENTITY`。
- 使用 BIGINT 的表必须通过业务字段建立包含 `workspace_id` 的唯一约束。
- 对外 API 不得依赖 BIGINT 的连续性表达业务顺序或数量。

### `DEC-020` 金融数值精度和币种

状态：已确认。

| 语义 | PostgreSQL 类型 |
| --- | --- |
| `price`、`spread` | `numeric(20,8)` |
| `money`、`fee`、`pnl` | `numeric(24,4)` |
| `ratio` | `numeric(20,10)` |
| `lots` | `bigint` |

- 金融数据不得使用浮点数作为数据库最终存储类型。
- 数据库模型支持 `currency_code`，默认 `CNY`。
- MVP 界面仅开放人民币，不实现汇率换算。
- Rust 领域和数据库边界使用十进制定点类型；浮点数只允许用于明确误差范围的临时统计计算。

## 7. 导入和回滚

### `DEC-021` 批次回滚

状态：已确认。

- 只有在导入批次不存在后续修改和下游引用时，才允许整批原子回滚。
- 存在后续修改或依赖时必须中止整个回滚并显示冲突清单。
- 不支持部分回滚。
- 纠错使用新的补偿批次，补偿批次必须引用原批次并接受完整审计。

## 8. 凭据和浏览器安全

### `DEC-022` 信封加密和主密钥

状态：已确认。

- 敏感数据使用信封加密：数据由 DEK 加密，DEK 由版本化主密钥/KEK 包裹。
- 主密钥不得存入数据库、代码仓库或 Docker 镜像。
- 密文记录保存加密算法、`wrapped_dek` 和 `kek_version`，不保存主密钥本身。
- 主密钥轮换通过重新包裹 DEK 完成，不要求解密并重写全部业务明文。
- 数据库备份与主密钥恢复副本必须分开保存。

### `DEC-023` 远程人工登录

状态：已废止（由 `DEC-031` 替代，2026-08-02）。

以下为原决策内容，仅为变更审计保留，不再生效：

- 远程登录使用隔离 Chromium 容器、Playwright 和 noVNC。
- 每个 Workspace 与数据源组合使用独立 Browser Context。
- noVNC 会话必须短期授权、不可直接公开暴露，并与应用 session 绑定。
- 登录状态使用信封加密保存，不得写入 Git、普通日志或未加密对象。
- 采集浏览器与图表渲染浏览器必须保持独立信任边界。

## 10. Phase 1 补充决策

### `DEC-026` 首次用户初始化

状态：已确认。

- 系统中不存在用户时，允许访问一次性初始化接口或初始化页面。
- 初始化必须校验一次性 bootstrap token。生产与 VPS 环境使用 `BOOTSTRAP_TOKEN_FILE` 指向只读挂载文件，当前 futures VPS 约定宿主路径为 `/etc/futures-platform/secrets/bootstrap-token`，`root:root` 且权限 `0400`；不得写入 Git、数据库、镜像、日志或普通 `.env`。开发环境可使用等价临时文件；环境变量 `BOOTSTRAP_TOKEN` 仅允许非生产本地调试。
- 初始化在单个数据库事务中创建首个管理员用户、个人 Workspace 和 Workspace Owner 成员关系。
- 初始化不自动创建虚构交易账户。
- 首个用户创建成功后，初始化入口永久关闭，并立即使 token 失效；文件来源的 token 必须删除。
- 并发初始化只能有一个请求成功，必须通过集成测试验证。

### `DEC-029` futures VPS 主密钥托管

- 主密钥只读挂载给需要解密的容器。
- 数据库只保存 `wrapped_dek`、`kek_version`、`nonce` 和算法信息。
- 支持主密钥版本轮换；离线恢复副本与数据库备份分开保存。
- 部署文档必须写明恢复和轮换步骤，且不得泄漏明文密钥。

## 11. Agent 工作流与上下文交接

### `DEC-036` Planner/Generator/Evaluator 工作流

状态：已确认。

- 主 Agent 负责编排，固定使用 Planner、Generator、Evaluator 三个角色。
- 工作流为：Planner 制定计划 → 文档审查 → Planner 修正文档 → Generator 实现 → Evaluator 审查 → Generator 修复 → Evaluator 复核 → 全部验证通过 → Git 提交。
- Planner 不写业务实现代码；Generator 不改变已确认业务口径；Evaluator 原则上只读并输出证据化审查。

### `DEC-037` 上下文轮换与交接

状态：已确认。

- 上下文接近上限、阶段完成、日志/代码积累过多、用户要求换新 AI 或 AI 无法可靠记住前序决策时，必须执行交接。
- 交接文档使用不可覆盖路径 `docs/handoffs/HANDOFF_YYYYMMDD_HHMM.md`。
- `docs/handoffs/LATEST.md` 只指向并概括最新交接状态，不删除历史文件。
- 交接必须记录 Git、未提交修改、任务状态、决策、测试、VPS、迁移、服务和下一步第一条操作。
- 交接文档不得包含密码、API Key、Cookie、Token、主密钥、数据库明文凭据或其他秘密。
- 新 AI 必须通过 Git、测试和运行环境核验交接内容，不得盲目信任摘要。

## 12. 总方案重审决策

### `DEC-038` 自动采集免确认

状态：已确认。

- 白名单数据源的结构化自动采集数据免人工确认、免提取预览，直接进入正式表。
- 兜底机制：解析或校验失败的批次自动隔离为 `failed`，不写正式表；批次可整批回滚；数据质量警告仅记录、不拦截。
- 人工确认仅保留于手动文件导入的既有流程，该流程不变。

### `DEC-039` 采集范围与历史回填

状态：已确认。

- 范围：全市场日行情（收盘价与结算价）、全市场席位龙虎榜（各合约成交量、持买、持卖排名）、交易日历、合约参数。
- 历史回填全部可得历史。
- 执行策略：行情全量一次拉取；席位倒序分层，先近 5 年，再由后台任务向更早年份补拉；不可得年份留记录、不阻塞。
- 磁盘达到 80% 水位时扩容 VPS 磁盘，不更换机器。

### `DEC-040` 图表导出

状态：已确认。

- 不建服务端图表渲染沙箱。
- PNG/SVG 由 ECharts 前端直接导出。
- SVG 安全清洗验收条款保留。

### `DEC-041` DCE 采集来源例外

状态：已确认（2026-08-02）。

- 实证依据：2026-08-02 从国内网络直连 `www.dce.com.cn` 首页、行情接口并使用浏览器 User-Agent 均返回 HTTP 412；VPS 同样返回 412；AKShare 上游已记录“大商所所有接口返回 412 待解决”。该现象属于 DCE 全局 WAF 挑战，不是单一出口 IP 问题，因此不建设独立采集出口。
- DCE 固定采用“官方直连优先、经审核聚合源自动 fallback”：每次仍先调用 AKShare 封装的大商所官方接口；发生 HTTP 412 或等价的网络、响应格式、解析失败时，自动切换到经审核的聚合源。AKShare 上游修复后，优先级逻辑无需改动即可自动恢复一手来源。
- Phase 4A 经审核的 fallback 固定为新浪期货接口：其 AKShare `futures_zh_daily_sina` 同时提供指定合约的历史收盘价与结算价，`futures_hold_pos_sina` 提供指定日期、逐合约的成交量、持买和持卖排名；东方财富 `futures_hist_em` 缺少结算价，因此不选用。
- fallback 数据必须如实使用独立 `data_sources` 记录和域名白名单；批次、`market_prices.source_id`、`seat_positions.source_id` 必须指向新浪聚合源，不得标注为 DCE 官方。官方失败尝试与 fallback 成功批次均须可审计、可追溯。
- 该例外仅限 DCE；SHFE、CZCE、GFEX、CFFEX 继续只允许官方直连，不得引入聚合源。

### `DEC-044` 大商所官方历史文件接入

状态：已确认（2026-08-09，运营者授权）。

- 背景：焦煤（2013-03 上市）与鸡蛋（2013-11 上市）在 2013–2018 的逐合约行情，
  此前判定为「拿不到」。该判定是**错的**，错在只试了 AKShare 封装的接口与聚合站，
  没有查交易所官网自己的历史下载页。实证（2026-08-09）：
  - 大商所官方 API 仍全线 412（`DEC-041` 的 WAF 问题未解，当日复测首页与行情页均 412）
  - 新浪逐合约只保留到约 **2018-09**（`JM1909` 有、`JM1801`/`JM1901` 全空）
  - 东方财富**一条退市合约都不保留**（`114.jm1909` 亦为空，仅在市 14 个合约）
  - 三禾逐合约仅 **2026-01 起 7 个月**
  - **大商所官网历史下载页有 2006 年起的年度逐合约文件**，且含结算价
- 接口：`GET /dcereport/quote/history/download?type=1&year=YYYY&variety=<id>&lang=zh`，
  返回 `<variety>_ftr.xlsx`。工作表「日历史行情」，列含商品名称、合约名称、交易日期、
  开高低收、前结算价、**结算价**、涨跌、成交量、持仓量、持仓量变化、成交额。
- **取得方式：运营者用浏览器一次性下载，不做自动化。** 该站 WAF 拒绝脚本客户端
  （VPS curl 同一 URL 仍 412），**不得编写任何绕过机器人检测的代码**。这对本数据成立
  是因为**历史不可变**：一次性取得后永远正确，与每日采集的性质不同。
- 采集器以本地文件源读取：来源代码 `dce_official_history`，类型 `exchange_public`、
  授权 `whitelisted`、连接器 `dce_history_files_v1`（迁移 `202608100001` 放行）。
  **域名白名单为空**——该源永不打开套接字，将来若有人试图从这里发请求，出站围栏会直接拒绝。
- 落库仍走既有导入通道，按交易日一批（catalog → calendar → market），审计批次、
  来源标注、RLS 全部复用。`market_prices` 业务唯一键含 `source_id`，故与新浪/官方源的
  行共存不冲突：同一交易日可由多个来源各自作证。
- 该源**不承担席位**。这些年份的席位在交易所的日排名归档里
  （`/dcereport/publicweb/dailystat/memberDealPosi/batchDownload`，实测 2013-06-14 可得），
  属另一次一次性取得，未在本决策范围内。

### `DEC-043` 东方财富席位聚合源接入

状态：已确认（2026-08-09，运营者授权）。

- 背景与实证：`DEC-041` 当初选新浪不选东方财富，理由是东方财富 `futures_hist_em`
  缺少结算价，无法承担行情数据。该理由**只对行情成立，对席位不成立**。2026-08-09
  实证东方财富数据中心报表 `RPT_FUTU_DAILYPOSITION` 同时覆盖 SHFE、DCE、CZCE、CFFEX、
  GFEX、INE 六个市场的成员级成交持仓龙虎榜，单日约 9939 行（`TYPE="0"`），且当日即可
  取到当期交易日数据。
- **接口更正**：早期交接文档记录的
  `qhhqzl.eastmoney.com/marketFutuWeb/dragonAndTigerInfo/getLongAndShortPosition`
  是错的，该地址对任何参数组合都返回 `code:40000`。实际在用的是
  `datacenter-web.eastmoney.com/api/data/v1/get`，报表名 `RPT_FUTU_DAILYPOSITION`，
  过滤条件 `(TRADE_DATE='YYYY-MM-DD')(TYPE="0")`，`SECURITY_CODE` 大写，`pageSize`
  被服务端硬性截到 500。
- 定位：**只服务席位（`seat_positions_v1`），永远排在官方源之后**。它不提供结算价，
  也不提供合约目录，因此不得承担 `daily_market_prices_v1`、`futures_catalog_v1`、
  `trading_calendar_v1` 任何一项——采集器对此有显式拒绝。
- 顺序：官方 → （仅 DCE）新浪 → 东方财富。官方在应答时永远不会被抢先，`DEC-041`
  的“官方优先”不受削弱；本决策只是把原先“官方失败即整块席位失败”的情形，变成还有
  一次尝试。适用于全部五家交易所，这是它相对新浪例外的唯一扩大之处。
- 连接方式：AKShare 1.18.81 **没有**任何东方财富期货席位函数，因此该源不经 AKShare，
  由采集器自有 HTTP 客户端直连，并受与 AKShare 路径完全相同的域名白名单与 DNS 围栏
  约束（`official_requests_only`）。为不谎报取数方式，其 `connector_code` 独立为
  `eastmoney_seats_v1`，不复用 `akshare_v1`；迁移 `202608090002` 放行该值。
- 如实标源：`data_sources.code = eastmoney_seats_fallback`，类型 `aggregator_public`，
  授权状态 `whitelisted_exception`，域名白名单仅 `datacenter-web.eastmoney.com`，
  优先级 40（低于新浪 50，低于官方 100）。落库批次与 `seat_positions.source_id`
  必须指向该源，不得标注为交易所官方。
- INE（上期能源，`069001016`）在该报表中存在，但**不属于本平台编目的五家交易所**，
  一律排除；否则会凭空造出任何目录数据集都未声明过的合约。
- 完整性：报表分页若超出页预算，整日判为失败而不是提交被截断的席位表。

### `DEC-042` 三禾只读 API 接入

状态：已确认（2026-08-05，用户授权；具体实施仍须先确认 Phase 5 Planner 契约）。

- `sanheshuju.com` 加入数据源与出口白名单，数据源类型固定为 `aggregator`，UI
  如实显示“数据来源：三禾数据”。本决策只恢复无需登录的只读 API，不恢复已废止的
  Chromium、Playwright、noVNC、登录会话或凭据基础设施。
- Phase 5 首期只允许服务端 `POST` 调用
  `/ajax/arbitrage_varieties.php`、`/ajax/all_varieties.php` 和
  `/ajax/variety_contracts.php`。前端不得直连；三禾席位持仓及其他接口不在授权范围，
  留待 Phase 7 另议。
- Rust API 新增 `sanhe` 适配器并通过 `SpreadSeriesProvider` 应用端口使用。该端口
  同时提供 `sanhe` 首发实现和 `self_hosted` 自有行情实现，保证上游变化或自有回填
  恢复后可替换 provider，而不改变页面主查询契约。
- 所有实际三禾请求之间至少间隔 1.5 秒；同端点、同规范化参数在
  `Asia/Shanghai` 同一业务日期只取一次并持久缓存，缓存记录取数时间。并发 cache miss
  必须跨 API 实例串行化，不能形成惊群。
- HTTP 200、业务码 `code:0` 且 data/序列为空是合法空结果，必须与网络、HTTP、
  业务码和字段契约错误分开。适配器失败映射为稳定平台错误，不转发上游正文；cache
  miss 只尝试一次，不自动重试轰炸，也不以过期缓存伪装当日结果。
- 三禾历史接口只返回已计算差值和两腿实际合约代码，没有原始腿价格。Phase 5A 必须
  按每点 `from_code`/`to_code` 对照本库合约交割月，使用版本化“散户可交易窗口”规则
  截取并拼接；季节图和月度矩阵由截取后序列在平台服务端重算。三禾
  `year_data`、`stat_ret`、`stat_rate` 仅可用于受控调试对照，不作为用户统计真值。
- 默认窗口起点为两腿均有有效数据的首日；止点为较早交割腿“交割月前一月最后一个
  交易日”，并允许按品种发布版本化覆盖规则。算法与交易日历版本、段界、排除数量和
  取数时间必须可追溯，并以跨年、晚上市和规则覆盖单测固定。
- 三禾接口没有公开版本或稳定性承诺。字段、鉴权或访问限制变化时必须稳定失败并停止
  扩大请求，不得临时加凭证、提高频率、扩大端点或绕过限制。

影响与优先级：本决策是 `DEC-024`、`DEC-025`、`DEC-031` 中“三禾/聚合源不进入
第一批”对 Phase 5 自由价差的用户授权特例。上述决策对 Phase 4 五交易所 akshare
采集仍完全有效；`DEC-041` 的 DCE fallback 也不受影响。详细数据、API、页面和验收
契约见 `docs/phases/PHASE_05_SPREAD_ANALYTICS.md`。
