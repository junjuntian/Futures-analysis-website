# 三家交易所原始字段对照（2026-08-10 实测）

先采、再分析、再建表、最后灌数据——这份文档是第二步的产物。此前的做法是边灌边改表，
一天之内因为"表里没有这一列"返工四次，所以先把三家到底给什么摊开看清楚。

所有结论都来自当天实际取到的文件，不是文档或记忆。

## 1. 取得方式

| 交易所 | 品种 | 行情 | 席位 |
| --- | --- | --- | --- |
| 大商所 DCE | JM JD LH | **年度文件** `jm_2015.xlsx`（2013–2024 已下载 28 个） | 东财报表 `RPT_FUTU_DAILYPOSITION`（已实证） |
| 郑商所 CZCE | AP FG SA | 逐日 `.../Future/{年}/{日期}/FutureDataDaily.txt` | 逐日 `.../FutureDataHolding.txt` |
| 上期所 SHFE | AU AG | 逐日 `.../future/dailydata/kx{日期}.dat` | 逐日 `.../dailydata/pm{日期}.dat` |

**三条必须记住的取数事实：**

1. **郑商所必须走 https**：http 返回 301，且 `curl` 不跟随重定向就拿不到。
2. **郑商所席位只能取 `.txt`**：同目录的 `.htm` 返回 **412**（WAF）。`.txt` 与 `.xls` 都是 200。
   与大商所同一规律——静态数据文件放行，HTML 页面被挡。
3. **郑商所与大商所的官网 HTML 页都进不去**（412），但静态数据文件可以。
   不得为被挡的路径编写任何绕过机器人检测的代码。

## 2. 行情字段对照

| 含义 | 大商所 2013–2018 | 大商所 2019–2024 | 郑商所 | 上期所 |
| --- | --- | --- | --- | --- |
| 合约 | `合约名称` jm1601 | `合约` jm1901 | `合约代码` **AP501（大写）** | **无现成列**：`PRODUCTID`=`au_f` + `DELIVERYMONTH` 拼 |
| 日期 | `交易日期` 20150901 | `日期` 20190102 | **不在行内**，在表头「(2024-12-02)」 | **不在行内**，在 `o_day` |
| 开盘 | `开盘价` | `开盘价` | `今开盘` | `OPENPRICE` |
| 最高 | `最高价` | `最高价` | `最高价` | `HIGHESTPRICE` |
| 最低 | `最低价` | `最低价` | `最低价` | `LOWESTPRICE` |
| 收盘 | `收盘价` | `收盘价` | `今收盘` | `CLOSEPRICE` |
| 结算 | `结算价` | `结算价` | `今结算` | `SETTLEMENTPRICE` |
| 前结算 | `前结算价` | `前结算价` | `昨结算` | `PRESETTLEMENTPRICE` |
| 成交量 | `成交量` | `成交量` | `成交量(手)` | `VOLUME` |
| **成交额** | `成交额` **元** | `成交额` **元** | `成交额(万元)` **万元** | `TURNOVER` **万元** |
| 持仓量 | `持仓量` | `持仓量` | `持仓量` | `OPENINTEREST` |
| 持仓变化 | `持仓量变化` | 无 | `增减量` | `OPENINTERESTCHG` |
| 交割结算价 | 无 | 无 | `交割结算价` | 无 |

**归一时必须处理的差异：**

1. **成交额单位不同**：大商所是元，郑商所与上期所是**万元**。不换算的话郑商所的
   成交额会比真实值小一万倍，而"用成交额反推点值"这条校验会直接失效。
2. **成交量口径**：大商所页面注明**按双边计算**；郑商所自 2020 年起改为单边。
   同一列名下是两种含义，落库必须记录口径而不是假装相同。
3. **合约大小写**：郑商所大写 `AP501`，另两家小写。且郑商所是 **3 位月份**（`AP501`
   = 2025 年 1 月），另两家 4 位（`jm1601`）。世纪要按上市年份推，不能凭字面。
4. **日期不在行内**：郑商所在标题行、上期所在 JSON 顶层。逐行解析前必须先取到它，
   否则整批数据会落到错误的交易日上。
5. **数字带千分位逗号**：大商所与郑商所都带（`64,786`），上期所不带。
6. **上期所合约代码要拼**：`PRODUCTID` 是 `au_f` 这种带后缀的品种标识，不是合约代码。

## 3. 席位字段对照

| 含义 | 大商所（东财） | 郑商所 | 上期所 |
| --- | --- | --- | --- |
| 结构 | 每会员一行，三个名次列并存 | **分段纯文本**，按品种/合约分块，每段自带表头 | `o_cursor` 数组 |
| 合约标识 | `SECURITY_CODE` | 段落标题「合约：AP501」或「品种：苹果AP」 | `INSTRUMENTID` |
| 名次 | `VOLUME_RANK` / `LP_RANK` / `SP_RANK` | `名次` | `RANK` |
| 会员 | `MEMBER_NAME_ABBR` | `会员简称` **三列**（成交/持买/持卖各一个） | `PARTICIPANTABBR1/2/3` |
| 成交量 | `VOLUME` | `成交量（手）` + `增减量` | `CJ1` + `CJ1_CHG` |
| 持买 | `LONG_POSITION` | `持买仓量` + `增减量` | `CJ2` + `CJ2_CHG` |
| 持卖 | `SHORT_POSITION` | `持卖仓量` + `增减量` | `CJ3` + `CJ3_CHG` |

**两处对做界面直接有用的发现：**

1. **上期所自带品种汇总行**：`INSTRUMENTID` 出现 `cuall` 这种值，即该品种全部合约的
   汇总排名。运营者要求的「品种汇总」视图在上期所可以直接取，不必自己加总——
   而自己加总与交易所口径未必一致，能取到官方的就用官方的。
2. **郑商所同一段里三列会员名互不相同**：成交量榜第一名与持买榜第一名是两家公司。
   这与另两家一致，但它的表现形式是同一行里三对（会员，数值），解析时不能按行当作
   一个会员的三个指标。

## 4. 数据量与耗时

| 交易所 | 最早需要 | 交易日数（估） | 每日请求 |
| --- | --- | --- | --- |
| 郑商所 | 玻璃 FG 2012-12 上市 | 约 3,300 | 行情 1 + 席位 1 |
| 上期所 | 黄金 AU 2008-01 上市 | 约 4,400 | 行情 1 + 席位 1 |

每个请求返回该交易所当日**全部合约**，所以与品种数无关。合计约 **15,400 个请求**，
按 2 秒间隔约 **8.5 小时**，无人值守可完成。大商所行情已是本地文件，不占请求。
