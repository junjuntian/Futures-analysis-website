# 三家交易所原始字段对照（2026-08-10 实测）

先采、再分析、再建表、最后灌数据——这份文档是第二步的产物。此前的做法是边灌边改表，
一天之内因为"表里没有这一列"返工四次，所以先把三家到底给什么摊开看清楚。

所有结论都来自当天实际取到的文件，不是文档或记忆。

## 1. 取得方式

| 交易所 | 品种 | 行情 | 席位 |
| --- | --- | --- | --- |
| 大商所 DCE | JM JD LH | **年度文件** `jm_2015.xlsx`（2013–2024 已下载 28 个） | 东财报表 `RPT_FUTU_DAILYPOSITION`（已实证） |
| 郑商所 CZCE | AP FG SA | 逐日 `.../Future/{年}/{日期}/FutureDataDaily.txt` | 逐日 `.../FutureDataHolding.txt` |
| 上期所 SHFE | AU AG | 逐日 `.../future/dailydata/kx{日期}.dat` | 逐日 `.../dailydata/pm{日期}.dat` |

**三条必须记住的取数事实：**

1. **郑商所必须走 https**：http 返回 301，且 `curl` 不跟随重定向就拿不到。
2. **郑商所席位只能取 `.txt`**：同目录的 `.htm` 返回 **412**（WAF）。`.txt` 与 `.xls` 都是 200。
   与大商所同一规律——静态数据文件放行，HTML 页面被挡。
3. **郑商所与大商所的官网 HTML 页都进不去**（412），但静态数据文件可以。
   不得为被挡的路径编写任何绕过机器人检测的代码。

## 2. 行情字段对照

| 含义 | 大商所 2013–2018 | 大商所 2019–2024 | 郑商所 | 上期所 |
| --- | --- | --- | --- | --- |
| 合约 | `合约名称` jm1601 | `合约` jm1901 | `合约代码` **AP501（大写）** | **无现成列**：`PRODUCTID`=`au_f` + `DELIVERYMONTH` 拼 |
| 日期 | `交易日期` 20150901 | `日期` 20190102 | **不在行内**，在表头「(2024-12-02)」 | **不在行内**，在 `o_day` |
| 开盘 | `开盘价` | `开盘价` | `今开盘` | `OPENPRICE` |
| 最高 | `最高价` | `最高价` | `最高价` | `HIGHESTPRICE` |
| 最低 | `最低价` | `最低价` | `最低价` | `LOWESTPRICE` |
| 收盘 | `收盘价` | `收盘价` | `今收盘` | `CLOSEPRICE` |
| 结算 | `结算价` | `结算价` | `今结算` | `SETTLEMENTPRICE` |
| 前结算 | `前结算价` | `前结算价` | `昨结算` | `PRESETTLEMENTPRICE` |
| 成交量 | `成交量` | `成交量` | `成交量(手)` | `VOLUME` |
| **成交额** | `成交额` **元** | `成交额` **元** | `成交额(万元)` **万元** | `TURNOVER` **万元** |
| 持仓量 | `持仓量` | `持仓量` | `持仓量` | `OPENINTEREST` |
| 持仓变化 | `持仓量变化` | 无 | `增减量` | `OPENINTERESTCHG` |
| 交割结算价 | 无 | 无 | `交割结算价` | 无 |

**归一时必须处理的差异：**

1. **成交额单位不同**：大商所是元，郑商所与上期所是**万元**。不换算的话郑商所的
   成交额会比真实值小一万倍，而"用成交额反推点值"这条校验会直接失效。
2. **成交量口径**：大商所页面注明**按双边计算**；郑商所自 2020 年起改为单边。
   同一列名下是两种含义，落库必须记录口径而不是假装相同。
3. **合约大小写**：郑商所大写 `AP501`，另两家小写。且郑商所是 **3 位月份**（`AP501`
   = 2025 年 1 月），另两家 4 位（`jm1601`）。世纪要按上市年份推，不能凭字面。
4. **日期不在行内**：郑商所在标题行、上期所在 JSON 顶层。逐行解析前必须先取到它，
   否则整批数据会落到错误的交易日上。
5. **数字带千分位逗号**：大商所与郑商所都带（`64,786`），上期所不带。
6. **上期所合约代码要拼**：`PRODUCTID` 是 `au_f` 这种带后缀的品种标识，不是合约代码。

## 3. 席位字段对照

| 含义 | 大商所（东财） | 郑商所 | 上期所 |
| --- | --- | --- | --- |
| 结构 | 每会员一行，三个名次列并存 | **分段纯文本**，按品种/合约分块，每段自带表头 | `o_cursor` 数组 |
| 合约标识 | `SECURITY_CODE` | 段落标题「合约：AP501」或「品种：苹果AP」 | `INSTRUMENTID` |
| 名次 | `VOLUME_RANK` / `LP_RANK` / `SP_RANK` | `名次` | `RANK` |
| 会员 | `MEMBER_NAME_ABBR` | `会员简称` **三列**（成交/持买/持卖各一个） | `PARTICIPANTABBR1/2/3` |
| 成交量 | `VOLUME` | `成交量（手）` + `增减量` | `CJ1` + `CJ1_CHG` |
| 持买 | `LONG_POSITION` | `持买仓量` + `增减量` | `CJ2` + `CJ2_CHG` |
| 持卖 | `SHORT_POSITION` | `持卖仓量` + `增减量` | `CJ3` + `CJ3_CHG` |

**两处对做界面直接有用的发现：**

1. **只有郑商所发按会员的品种汇总排名**：它的段落标题写「品种：苹果AP」而不是
   「合约：AP501」，段内是真实的会员名次。运营者要的「品种汇总」视图，郑商所三个
   品种可以直接用官方的。

   **更正（同日稍后实测）**：本文最初写着上期所的 `cuall` 也是品种汇总排名。
   **那是错的。**`auall` 只有两行且都不是会员：`RANK=-1` 名为「期货公司」、
   `RANK=0` 名为「非期货公司」，各是一个合计数。上期所与大商所都不发品种汇总排名，
   这两家的汇总必须由我们从逐合约行加总，并在行上标明是自算的。
   把那两行当会员会凭空造出两个不存在的席位。
2. **郑商所同一段里三列会员名互不相同**：成交量榜第一名与持买榜第一名是两家公司。
   这与另两家一致，但它的表现形式是同一行里三对（会员，数值），解析时不能按行当作
   一个会员的三个指标。

## 4. 数据量与耗时

| 交易所 | 最早需要 | 交易日数（估） | 每日请求 |
| --- | --- | --- | --- |
| 郑商所 | 玻璃 FG 2012-12 上市 | 约 3,300 | 行情 1 + 席位 1 |
| 上期所 | 黄金 AU 2008-01 上市 | 约 4,400 | 行情 1 + 席位 1 |

按 2 秒间隔约 **8.5 小时**，无人值守可完成。大商所行情已是本地文件，不占请求。

## 5. 可回溯范围（2026-08-10 逐日期实测）

每个日期都实际取过，不是推断。

| 交易所 | 行情最早实证 | 席位最早实证 | 结论 |
| --- | --- | --- | --- |
| 郑商所 | **2012-12-03**（玻璃上市首日）200 | **2012-12-03** 200 | 三个品种自上市起全可得 |
| 上期所 | **2008-01-09**（黄金上市首日）200 | **2008-01-09** 200 | 两个品种自上市起全可得 |
| 大商所 | 年度文件 2013–2024 | **不可得**，见下 | 行情齐、**席位有缺口** |

**郑商所两套路径都通**，分界在 2015-11-11：

- 2015-11-11 及以前：`/cn/exchange/{年}/datadaily/{日期}.txt`、
  `/cn/exchange/{年}/datatradeholding/{日期}.txt`
- 之后：`/cn/DFSStaticFiles/Future/{年}/{日期}/FutureDataDaily.txt`、`FutureDataHolding.txt`

实测 2013/2014/2015/2015-12/2017/2019/2021/2023/2025 九个日期，行情与席位**全部 200**。
（2010-08-24 之前还有一套 HTML，但我们最早只需要 2012-12，用不到。）

**上期所不需要旧主机**：`www.shfe.com.cn` 直接服务 2008 年至今，行情与席位皆然。
`tsite.shfe.com.cn` 已连不上（实测 000），akshare 常量里的旧地址不必再用。

### 大商所席位：目前无可用来源

- **交易所官方**：`memberDealPosiQuotes.html` 对脚本客户端返回 **412**，在真实浏览器里
  返回 **500**。两种方式都拿不到，且 500 说明是该接口自身的问题，不只是 WAF。
- **东方财富**：实测每个交易日的行数——

  | 交易日 | 行数 |
  | --- | --- |
  | 2025-08-01 及更早 | **0** |
  | 2025-11-03 | 249 |
  | 2026-01-05 | 1,070 |
  | 2026-03-02 | 2,006 |
  | 2026-06-01 | 6,173 |
  | 2026-08-07 | 9,939（完整） |

  它**不是历史源，是一张still在补的报表**：2025-11 才开始有数，且直到 2026 年中都只有
  完整市场的一小部分。`DEC-043` 记的"只到约 2025-11"方向对，但没记它在那之后仍然残缺。

**因此：焦煤、鸡蛋、生猪三个品种的席位，官方与东财都补不上 2025 年。**
另五个品种（苹果、玻璃、纯碱、黄金、白银）自上市首日起完整可得。

### 大商所席位的补法：三禾（运营者 2026-08-10 指示）

实测三个免登录接口，与 `DEC-042` 已授权的三个是不同的一组：

| 接口 | 返回 |
| --- | --- |
| `ajax/broker_dates.php` | `first_date` **2023-08-10** / `last_date` 2026-08-07 |
| `ajax/all_brokers.php` | 会员名录，**208 家**，含评级 |
| `ajax/broker_positions.php` | 参数 `broker` + `date`；返回该会员当日在**全部品种**上的逐合约 `buy`/`ss`/`buy_chge`/`ss_chge` |

- **覆盖 2023-08-10 起满三年**，完全包住运营者要求的 2025-01-01，还多出一年半。
  实测 2025-01-02 有 68 个品种、2024-06-03 有 65 个、2023-06-01 为空——与 `first_date` 一致。
- **组织方式是「按会员」而不是「按合约」**：三禾自己的席位页就是选一个会员看它的持仓，
  所以没有按合约的接口。要拼出「某合约当日的席位表」，必须把会员逐个取一遍。
- 三禾的来源仍是交易所公布的前 20 名榜单，所以「取遍所有会员」得到的是**同一份前 20 数据
  的另一种排列**，不会比交易所更全，也不会更少。

**请求量**：2025-01-01 至今约 395 个交易日 × 208 家 ≈ **8.2 万次请求**。按 2 秒间隔约 46 小时。
可先用少数几天把 208 家全取一遍，筛出「曾在大商所三品种榜上出现过」的会员（预计 60–80 家），
其余日期只取这批，可降到约 2.5 万次、14 小时。
