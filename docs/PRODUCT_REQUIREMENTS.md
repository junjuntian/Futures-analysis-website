# 产品需求

## 1. 产品目标

为个人或小团队提供本地部署的期货数据研究与交易复盘平台，统一完成数据导入、来源追溯、确定性统计、图表展示和受控 AI 解释。

成功标准不是“抓取尽可能多的数据”，而是：

- 同一数据和参数可重复得到同一统计结果。
- 任一汇总值可追溯到原始记录、来源和处理批次。
- 错误批次可恢复，不污染后续统计。
- 权限、敏感信息和外部访问受到明确控制。

## 2. 用户与角色

| 角色 | 主要能力 |
| --- | --- |
| `admin` | 用户、权限、数据源、密钥、系统配置、回滚、审计 |
| `analyst` | 录入、导入、计算、图表、AI 分析 |
| `viewer` | 只读查看数据、图表和报告 |

### 2.1 Workspace 归属

- 业务数据归属于 `Workspace`，不直接归属于 `User`。
- MVP 中每个用户只有一个个人 Workspace，不提供共享、邀请或成员管理。
- 账户、导入批次、数据源、行情、套利、交易、持仓、席位、图表、报告、任务和 AI 对话均以 `workspace_id` 隔离。
- 服务端从当前 session 解析 Workspace；客户端不得通过修改参数切换到其他 Workspace。
- `admin` 角色不自动获得其他 Workspace 的业务数据访问权；系统用户管理权限与 Workspace 业务数据权限分离。

## 3. 功能需求

### 3.1 身份、权限与审计

- 用户名和密码登录，密码使用 Argon2id 哈希。
- 使用服务端 Cookie Session；登录、提权和密码修改后轮换 session。
- 所有写操作、回滚、权限变更和密钥操作产生审计记录。
- 审计记录不得包含密码、Cookie、API Key 或完整敏感载荷。

### 3.2 基础数据

- 管理 `exchange`、`instrument`、`contract`、`trading_calendar`。
- 统一品种代码、合约代码、币种、合约乘数、最小变动价位和价格类型。
- 时间点以 UTC/`timestamptz` 保存，默认业务时区为 `Asia/Shanghai`。
- 市场数据分别保存 `trade_date` 和 `session_type`；夜盘按交易所交易日历归入下一交易日。
- 交易日历按交易所分别维护，支持版本和人工修正。
- 收盘价和结算价分别保存；任何分析结果必须标记 `price_basis`。
- MVP 不自动生成连续合约。外部连续合约数据必须标记来源和换月规则，后续内部换月规则及换月事件必须版本化。

### 3.3 导入中心

- 支持 TXT、CSV、XLS、XLSX。
- 提供格式识别、编码/分隔符选择、工作表/表头选择、字段映射、前 50 行预览。
- 每一行显示原始值、规范化值、错误和冲突。
- 冲突策略支持 `skip`、`overwrite`、`keep_both`、`abort`；各数据集可限制允许的策略。
- 导入在后台执行，状态和计数可查询，成功批次可整批回滚。
- 原始文件、SHA-256、映射版本、导入参数和错误报告必须保留。
- 只有不存在后续修改和下游引用的批次才能整批原子回滚；冲突时中止整个回滚，不支持部分回滚，纠错使用补偿批次。
- 白名单数据源的结构化自动采集批次免人工确认、免提取预览，使用固定映射模板版本后直接进入正式表；手动文件导入的既有预览与人工确认流程不变。
- 自动采集批次解析或校验失败时自动隔离为 `failed` 且不写正式表；数据质量警告仅记录、不拦截；成功批次继续支持整批回滚。

### 3.4 套利分析

- 支持任意多腿、系数和常数的价差定义。
- 保存每条腿的原始价格、价格类型、数据源、公式版本和计算批次。
- 提供描述统计、历史位置、季节性和路径统计。
- 缺失腿价格、非同步交易日、换月和价格来源冲突不得静默插值。
- 只提供历史统计、季节性、百分位、极值、回撤和情景计算。
- MVP 明确排除规则驱动的历史回测、模拟成交和自动交易信号。
- 行情图和普通价差分析默认使用收盘价；非默认价格口径必须由用户显式选择并显示。

### 3.5 成交与持仓

- 录入成交明细、完整交易组、每日持仓快照和每日权益。
- 仅从完整可配对的开平仓交易组计算胜率。
- 支持已实现/未实现盈亏、手续费、盈亏比、期望收益、Profit Factor 和最大回撤。
- 原始成交不可覆盖；纠错通过冲销或补偿记录完成。
- 开平配对默认 FIFO；加权平均只用于展示当前持仓成本。
- 已实现净盈亏使用实际成交价并包含手续费。
- 日终持仓、未实现盈亏和权益默认使用结算价。
- 数据库支持 `currency_code`，默认 CNY；MVP 界面不开放其他币种和汇率换算。

### 3.6 席位分析

- 保存原始席位名称、标准席位、别名、排名、成交量、多空持仓及增减仓。
- 分类为 `institutional_tendency`、`industrial_tendency`、`retail_tendency`、`mixed`、`unclassified`。
- 分类必须带规则版本、证据、可信度和有效期，不得表述为最终投资者身份事实。
- 任一汇总结果可下钻到原始席位行。

### 3.7 图表

- 生成价差、季节性、收益、回撤和席位图。
- 价差图支持 0 轴、正红负绿、当前值虚线、背景区间和水印。
- 正负颜色必须在过零点插值拆分。
- 支持交互查看；PNG/SVG 由 ECharts 前端直接导出，不建设服务端静态图导出能力；SVG 输出需要安全清洗。

### 3.8 akshare 自动采集

- 第一批一次覆盖 DCE、SHFE、CZCE、GFEX、CFFEX，只采集交易所公开数据；东方财富等二手数据源不进入第一批。
- 独立 Python akshare 采集器容器每交易日盘后由调度按需拉起，跑完退出，不常驻。
- 数据获取路径固定为 akshare 封装的交易所公开接口与公开文件；采集器输出标准化 CSV 后调用平台导入 API。
- 自动采集保留来源、任务、批次、变更日志与整批回滚全套机制。
- 采集范围为全市场日行情（收盘价与结算价）、全市场席位龙虎榜（各合约成交量、持买、持卖排名）、交易日历和合约参数。
- 历史回填覆盖全部可得历史：行情全量一次拉取；席位先近 5 年，再由后台任务倒序补拉更早年份；不可得年份留记录、不阻塞。
- 采集容器只允许访问交易所域名白名单；不开放任意 URL。
- 登录类数据源不在本期范围，如未来需要另行立项。

### 3.9 AI 分析

- 通过统一网关适配 OpenAI、Grok、Gemini。
- 模型只能调用经过授权的只读业务工具，不直接持有数据库凭据。
- 确定性统计由应用服务执行，模型只解释结果。
- 回答显示数据截止日期、样本区间、排除规则和来源。
- 记录模型、提示模板版本、工具调用、用量、延迟和错误。

## 4. 非功能需求

- 一致性：正式导入与回滚使用事务或可证明等价的补偿流程。
- 可追溯：正式数据必须有 `source_id`、`batch_id` 或人工操作记录。
- 隔离：所有业务表和后台任务必须以 `workspace_id` 作为强制租户条件。
- 安全：防 CSRF、SSRF、文件炸弹、提示词注入和敏感信息泄漏。
- 可恢复：数据库、对象文件和加密主密钥需要一致备份并定期恢复演练。
- 可观测：请求、任务和导入批次使用关联 ID；关键指标可统计。
- 性能目标、容量、RPO、RTO 和保留周期待确认，不自行设定。

## 5. MVP

MVP 包含：

1. 登录、权限和审计。
2. 基础数据与 TXT/CSV/XLS/XLSX 导入。
3. 多腿套利定义、价差序列和目标图表。
4. 成交、交易组、持仓快照和核心复盘指标。
5. 来源、版本、批次和回滚。

akshare 采集、席位分析、AI 和自动化在 MVP 验收后按 Phase 4 至 Phase 9 路线进入。

## 6. 明确排除

- 自动下单或账户交易控制。
- 绕过验证码、付费墙、登录限制或反爬机制。
- 未经授权的批量采集和二次分发。
- AI 写数据库、自动修正数据或生成确定性指标。
- Kubernetes、Kafka、复杂微服务、多租户 SaaS。
- 分钟级实时行情、规则驱动的历史回测和自动生成连续合约。
