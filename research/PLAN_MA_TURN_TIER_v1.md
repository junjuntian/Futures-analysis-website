## 一、数据与口径(事前写死)

**数据源**:生产 `qh` 的 `spread_monitor_daily`,导出到 `research/data/`。
它是采集 SQL `compute-spread-monitor.sql` 的产物,**页面读的就是这张表**,
所以回放与页面同源,不另造一套价差序列。

MA 现状(2026-09-16 查):**29,529 行 / 180 个组合 / 2014-12-26 ~ 2026-09-15**,
`turn_crosses` 素材 29,529 行全有(全史已回算)。行数是全品种最多的一个。

**一处必须写明的差别**:MA **没有配 `main_month`**(DEC-241 给 FU 立的规矩:
没点名就不限制月份),所以它的组合宇宙是「所有通过 `oi_rank <= 6` 流动性门的
月份对」,比 JM/JD/FG/SA/AP(都配了 `main_month`)**宽**。
档位结论是在这个更宽的宇宙上得到的,不能直接搬给配了主力月的品种。

### 进场判定 = 生产同款(照抄 `SpreadMonitorView.isQualifiedEntry`)

逐行按候选档 X 重算,四个条件全中才算一笔进场:

1. **已拐头**(`monitor_turn`,`TURN_BAND = 0.03` 不动):
   - `high`:`pair_pos_hi20 >= 0.97` 且 `pair_position <= 1 − X`;
   - `low`: `pair_pos_lo20 <= 0.03` 且 `pair_position >= X`;
   - 两侧同时成立取**离自家门槛更近**的一侧(DEC-088);
2. **今天刚拐头**(`monitor_turn_is_new`):high 要 `prev_pair_position > 1 − X`,
   low 要 `prev_pair_position < X`;
3. **本轮首次穿线**:按 X 重算近 20 个交易日的穿线计数(照抄采集 SQL 的
   `cross_h` / `cross_l` 定义),`== 1` 才算;
4. **未进交割红线**:`days_left > 15`。`days_left` 照抄
   `days_to_window_end`(两腿各取交割月前月最后一个非周末日,取先到期那个,
   数其间的非周末日)——**它数的是工作日不是真交易日,照抄就是照抄,不修**;
5. **资格合格**:拐头侧的 `revert_*_drift > 0`(`isQualified`,DEC-098 之后只剩这一条)。

**`turn_crosses` 与 `revert_*` 的区别要记住**:前者依赖档位,必须按 X 重算;
后者与档位无关,直接用库里的值。

**每实例每侧只取首笔**(DEC-070 口径):同一个 `(contract_1, contract_2, side)`
一生只记第一笔,后面的不计。

### 结局口径

- 进场日 `T`,区间宽 `W = pair_high − pair_low`(取 `T` 当日的,不随后面滚动);
- 出场 = **窗口止点**(`days_to_window_end` 的那个 `end`,也就是资格门用的
  「持到期」的终点)。**故意与资格门同一个终点**:拿 A 口径评资格、拿 B 口径记分
  是 DEC-088 那次事故的形状;
- **幅度** `pnl_pp = 方向 × (S_exit − S_T) / W × 100`,方向 high 取 −1、low 取 +1
  (单位:占区间宽度的百分点);
- **MAE** = `T+1` 到出场之间朝不利方向的最大幅度,同单位,下限 0;
- **早进** = 进场之后到出场之前,`pair_position` **曾经回触报警带**
  (high 侧 `>= 0.97`,low 侧 `<= 0.03`)。DEC-070 测过全品种约 80% 会回触;
- **胜率** = `pnl_pp > 0` 的比例。

### 候选档

**`5% / 8% / 10% / 12% / 15% / 20% / 25%`,七档,就这七个,不加不减。**
(DEC-252 报了 5/8/10/20/25,并提到逐年最优档出现过 12% 与 15%。)

## 二、判据(事前写死,跑完照此执行)

**默认结局是维持 10%。** 下面四道门**全过**才建议改档;过不了就如实报
「测了,不改」,不许因为「测都测了总得有个结论」去挑一个好看的。

- **G1 机制**(DEC-075 立的规矩:只保留有机制的)。二选一,必须点名是哪一条:
  - **机制 A(支持浅档)**:最优档的**早进组中位幅度 > 0**(早进不受罚,
    JD 与 FU 靠的就是它),且早进组中位随档位加深**单调变差**;
  - **机制 B(支持深档)**:MA 的**位置日抖动中位排全场前二**,
    且 `10%` 线 < 2 倍日抖动(JM 靠的就是它:抖动 6.4pp、10% 线只有 1.5 倍宽)。
  - **两条都不成立 → 维持 10%,不看后面三道门。**
- **G2 全样本单调**:七档的**中位幅度**必须单调(允许并列),中间有翻转就不改。
  LH 与 FG 当年正是栽在这一条上(相邻档正负翻转 = 过拟合)。
- **G3 样本外改善**:逐年留一挑参(用其余年份挑最优档,应用到留出的那一年)的
  **OOS 中位**,必须比**固定 10%** 的 OOS 中位高 **≥ 3 个点**。
  (FU 是 +18.7 vs +8.0 = 10.7 点;AP 当年是 +16.5 vs +16.5 = 0,被否掉。)
- **G4 方向一致**:最优档相对 10% 的改善,在**均值、中位、胜率**三项上同号。

**逐年一致性 k/n 必须报,但不设门槛** —— DEC-252 明写燃油只有 5/9 仍然放行,
理由是「机制 + 单调 + OOS 三条」。本次照同一把尺,**但要在报告里把 k/n 写在显眼处**。

## 五、明确不做

## 六、已知的偏袒(报告里要照抄)

1. **`revert_*` 带跨年前视**。资格门用的 `drift` 是拿**同模板其它年份**的实例算的
   (采集 SQL 里 `f.c1 <> s.c1` 已把自己排除,所以「留一」这一层是有的),
   **但那些年份包括当前实例之后的年份**。
   这是**页面本身就有的性质**,回放照抄它,是为了忠实于页面;
   **它不等于「当时能这么做」** —— 这套数字回答的是「按今天这套规则回看，
   历史上会是什么样」,不是一份可交易的历史业绩;
2. **档位是在全样本上挑的**,七档里挑最好的一个,天然带多重比较。
   G3 的逐年留一就是为压这一条存在的,但七档 × 十一年也压不干净;
3. **MA 的组合宇宙比别的品种宽**(没有 `main_month`),见第一节;
4. **`days_left` 数的是工作日不是真交易日**(照抄生产),节假日多的年份会高估剩余;
5. 甲醇 2014-12 才起步,**2015 年只有半年多**,早年组合数远少于近年。
